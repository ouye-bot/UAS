## 一、语句形态

### 1.1 互认集树（第二棵 SM3-SMT）

| 项 | 设计值 | 说明 |
|---|---|---|
| 树 | SM3-SMT **深度 6 = 64 机构满树** | 与现役撤销树（深度 32）同工艺不同实例：内节点=SM3(左‖右)（64B 整块，fresh IV，每内节点=数据块+padding 块两组=深度×2 组） |
| 叶 | `leaf = SM3(orgId ‖ epoch ‖ root)` | orgId 4B BE + epoch 8B BE + root 32B（该机构锚根）= 44B 原像 → 32B 叶摘要；与 ⑥一期 FedRegistry 逐机构锚（orgId,epoch,root）三元组同源（聚合面算法定义换代：keccak256 现场计算 → SM3 摘要+树聚合，见 §四） |
| 键 | `key = orgId 低 6 bit`（orgId 由登记序 0..63 递增分配） | LSB-at-leaf 位序（与 app/ra/smt.py 权威位序同款，R3-0.1 红线工艺平移）；容量满（第 65 机构准入）=拒绝，退出机构叶保留但锚冻结（⑥一期语义） |
| 根 | `mutual_root`（公开**实例 27**，实例面 26→27） | 8 词 BE 折叠单值钉（与实例 23 同款 fold 约束：Σ2^{32k}·(Σ2^{4j}·shadow)==实例值） |
| 见证 | 叶摘要 + 6 兄弟子树根 + 6 路径位 | 路径位格 bool+recomb 双约束（洗白封堵工艺同现役 SMT：选择器无激活点=约束真空=封堵失效的 dump 定谳教训平移） |

### 1.2 电路内命题与两种绑定形态

电路增量本体=**深度 6 成员链**（12 组查表门 + mux/bool/recomb/fold 面），复用现役 SMT 织入三段式（PLAN/WIRES/EMIT）全套工艺。叶摘要 `leaf`（链起点 cur_0）的语义绑定二选一：

- **形态 A（最小形态，census 实测口径）**：`leaf` 为自由见证，互认集根钉（SM3 抗碰撞）锁死其自由度；「叶==SM3(orgId‖epoch‖root)」的绑定在**链面**（FedRegistry 锚公示面逐机构重算对拍，chain_smoke 扩展断言）与受理门资格面完成。电路只证明：存在叶 ∈ 互认集根下申请者键位。实例面 +1。
- **形态 B（闭环形态）**：叶原像三字段（orgId 8 词/epoch 16 词/root 8 词）进见证词格，电路内补 1 次 SM3 压缩计算叶摘要（**+2 组**）+ root 字段折叠值 == 实例 23（rev_root）等值约束（≈+10 条）——电路内同时绑定「我的撤销根 == 互认集内我机构当前锚」。此形态把实例 23 从「受理门裸对拍的链面根」升级为互认集承诺下的机构锚，密码学闭环，代价=叶原像词格（~32 advice 列）+压缩组+等值面。
- **推荐**：形态 A 先行（census 口径），形态 B 作为 T3 触发（第三方验证者要求电路自证锚绑定）后的加一档。两形态共享成员链本体，形态 B 增量单独列于 §三。

### 1.3 与现役撤销树的关系（语义拆分——防频繁换根的根因解）

🔴 **核心决策**：互认集根是**资格承诺面**（谁在互认集内+锚纪元），**不是实时撤销权威**；实时撤销权威仍是共享单树根（实例 23，现役语义零变化）。

- 若互认集叶内含的锚 root 逐锚实时更新 ⟹ 任一机构每次吊销（共享树换根+锚推根）都改变互认集叶 ⟹ 互认集根全变 ⟹ 根更新仪式频率=吊销频率，与「根更新走 governor 仪式防频繁换根」直接矛盾。
- 解法：互认集叶中的 `root` 字段锚定**快照时点的机构锚**（governor 仪式时点的 (epoch,root) 快照值），互认集根只在**机构准入/退出/锚首次登记**时经 governor 仪式重算公示（低频）；日常吊销=共享树换根（现役 onlyRA 即时）+FedRegistry 锚推根（⑥一期公示面）**不动互认集根**。
- 由此受理门对拍语义（§二）的两条等式各自独立成立：实时性由实例 23↔IdentityRegistry.revRoot 对拍（现役），资格性由实例 27↔FedRegistry.mutualRoot 对拍（新增）。

## 二、受理门对拍语义

新增对拍两条（authz/service.py 的 `_expect` 面+router.py 的链面回读）：

1. **资格对拍（新增）**：`实例 27（互认集根）== FedRegistry.mutualRoot()`（链上聚合面——SM3 形态互认集根存储槽，governor 仪式写入）。不等 ⟹ 409 `stale_mutual_root`（与现役 `stale_rev_root` 同构 fail-closed）。
2. **实时对拍（现役保持）**：`实例 23（rev_root）== IdentityRegistry.revRoot()`——语义零变化。
3. **归属对拍（门面资格）**：申请者 `org_id` 已登记于 FedRegistry（`orgs[orgId]` 存在且未 retired）——现役 unknown_org 422 语义延伸；「实例 23 ∈ 用户 org 当前锚」的密码学绑定按形态 A 在链面（锚公示叶摘要对拍）+形态 B 升级为电路内等值（§1.2）。
4. **受理门实例数硬检**：`len(inst) < 26` → `< 27`（A6 锚的换代面）。

## 四、链面与治理语义

1. **FedRegistry 新增**：`mutualRoot`（bytes32，SM3 形态互认集根）+ `mutualEpoch`（uint64）存储槽；`setMutualRoot(bytes32 root, uint64 epoch)` **onlyGovernor**（时间锁仪式：RA 提案→governor confirm×2→execute——与 AdminGovernor 既有仪式同构）。现役 `globalRevRoot = keccak256(逐机构 orgId‖epoch‖root)` 聚合面**保留为公示面**（A4 锚零删除），互认集根为其 SM3-SMT 形态对应物（算法换代理由：电路内 SM3 栈单一事实源——链面若用 keccak 聚合则电路无法对拍）。
2. **根更新仪式（防频繁换根）**：互认集根仅在 ①新机构准入登记 ②机构退出（retired 叶剔除重算）③锚首次登记 三事件后由 RA 发起 governor 仪式更新；日常吊销推锚**不触发**（§1.3 拆分）。仪式附带逐机构叶公示（orgId‖epoch‖root→叶摘要全表上链事件）供第三方离线重算对拍。
3. **跨域受理=互认集快照纪元化**：worker 见证分发按「互认集快照纪元」生成路径（mutualEpoch 对齐时点的兄弟树）；受理门缓存的快照纪元落后链上 ⟹ 409 `stale_mutual_root` 强制刷新（现役 stale_rev_root 同构门控工艺）；跨域申请（申请域≠签发域）与同域申请消费同一互认集快照——**匿名证明（电路不披露签发机构）下按快照对拍天然跨域一致**（这是相对复评 §6.2「per-org 树无法一致选根」的结构性回应：互认集根是全机构单一根，不存在选根问题）。
4. **第三方复验面**：pin 换代后电路自含互认集根钉（实例 27）——第三方凭 proof+verifier_param+链面 mutualRoot 即可复验成员性，无需信任受理门（T3 信号的响应面就绪）。

## 六、与复评报告的对照（本设计不推翻 NO-GO 的声明）

- 复评 §2.2 的「+2.5~6k」估算对象=「pk_RA 锚定结构重构+Merkle 成员证明」全包；本设计把**成员证明叶子**单独实测（census），F9 根手术仍按复评口径另行立项——两段成本在重评时分开对账，消除「叶子标价、根手术免费」的口径混杂（复评 §2.2 判词原文），但**不改变**「根手术是承重墙」的判断。
- 复评 §6.2「匿名证明下一致选根不可能」的判词针对 per-org 树选根；互认集单一根形态天然消除选根（§四.3）——这是本设计相对 per-org 路线的结构性优势，如实记入重评材料。
- 增益轴判断（§2.3 恒真命题）**维持**：本设计全部价值在 T1 后计息；census 与负例矩阵是把重评的「如果做」分支从估算升级为实测弹药。
