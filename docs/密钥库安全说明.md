# 飞证 · 密钥库安全说明（P1-A1/A2 交付文档，2026-09-23）

> 对应实现：gcs/web/src/lib/keystore.ts（40 项 web 测试中 9 项专测）。
> 边界先行：本说明描述**演示形态**的浏览器密钥库；生产形态终点=WebCrypto
> 非导出密钥 / SE-TCM 芯片（见 docs/生产部署与安全演进.md R2）。

> **2026-09-29 账户批更新**：三角色门户上线后，密钥库主路径升级为 
> **v3 单因子信封**——口令=唯一 KEK，密封件存服务器侧（任意设备登录可取回解封）。
> 恢复码/导出导入功能随服务器存储**退役**（下方 v2 双因子形态描述保留为历史档）。
> 口令丢失=钥不可恢复=凭证需重发（私钥不出端的注脚）。登录认证=SM2 挑战-应答
> 签名（服务端零口令材料）；KDF 21000 轮 SM3 迭代链不变（JS↔Python 逐字节对拍锚在案）。


## 一、七步生命周期流程

```
① 生成   登记确认时，浏览器 CSPRNG 生成 SM2 密钥对
         （私钥 sk 只存在于页面内存，public key 随承诺上链）
   │
② 双因子 设定访问口令（≥8 位，用户自选）
         系统生成 120bit 恢复码（CSPRNG·去易混字符·仅展示这一次）
   │
③ 密封   KEK1 = SM3迭代链KDF(口令, salt1, 21000轮)      ← SM4-GCM 加密 sk → enc
         KEK2 = SM3迭代链KDF(恢复码, salt2, 21000轮)    ← SM4-GCM 加密 sk → rec
         localStorage = {v:2, pk, enc, rec}             ← 零明文私钥（测试钉定）
   │
④ 使用   申请出证时：输入口令 → 派生 KEK1 → 解封 sk → 内存签名 → 会话缓存
   │       （sessionStorage——同标签页存活期保留【含刷新】，关闭标签/浏览器即焚；
   │        2026-09-28 安全深检 C-P1-1 后已入会话清理单源：换身份/重登记/退出即清）
   │
⑤ 锁定   关闭标签页/浏览器 = 会话与内存清零，需重新输入口令
   │
⑥ 恢复   忘记口令但本机密钥库仍在：粘贴恢复码 → KEK2 解封 → 重设口令
         （链上承诺原像不变——恢复不产生任何链上操作）。
   │     跨设备（2026-09-28 兑现）：入口页「导出密钥库备份」→ 下载备份文件
         （密钥信封+身份元数据，**元数据以恢复码 KEK 加密——文件零明文**）
         → 新设备「导入并恢复身份」（备份文件+恢复码+设定新口令）。
         恢复码自此为跨设备凭证；**备份文件与恢复码双双泄露=身份可被冒用**
         （与"攻击者拿到密文可离线试口令"同一威胁面，防线同为口令/恢复码
         熵——120bit 恢复码对在线枚举与离线穷举均不可行）。
   │
⑦ 丢失   恢复码与口令双失（或备份与信封同失）= 身份不可找回（链上承诺仍在
         但原像知识消失）
         唯一路径 = 重新登记（新承诺新授权，旧授权自然过期）
```

## 二、五个安全点

1. **口令强度 × KDF 成本 = 唯一防暴力防线**。本地密钥库没有服务器挡暴力破解——
   攻击者拿到 localStorage 密文可离线试口令。防线=两层：口令熵（强度分级引导）
   × KDF 迭代成本。**成本实测口径（2026-09-28 深检 C-P2 精化——此前"OWASP
   2023 对齐值"话术偏松：OWASP 哈希指南最低档存储成本高于本值约一个量级，
   本值是浏览器侧体验与成本的折中而非合规对标）**：SM3 迭代链 21000 轮，
   纯 JS 单次解封约 3.5s（原生档约 11ms——离线攻击者成本远低于 3.5s 体感，
   8 位纯小写口令在单 GPU 下天数级可破）。**缓解纪律=口令强度分级达到
   "中"以上方可登记（长度+字符类别双因子）**；演进项=提升轮数配合
   WebWorker 异步解锁（构造公开可审计；国密无 PBKDF2 标准，自建构造是
   诚实取舍）。
2. **SM4-GCM nonce 绝不复用**。每次密封用 CSPRNG 新生成 12B nonce——同密钥下
   nonce 复用是 GCM 的灾难性失败，测试与实现双重钉定。
3. **AAD 绑定用途与槽位**。口令密文 AAD=`FZ-KEYSTORE-v2|pass`、恢复码密文
   AAD=`|recovery`——两份密文不可互换挪用（挪用=tag 校验失败）。
4. **篡改必败且不泄细节**。密文改 1 字节 = GCM tag 校验失败，结构化拒绝
   （KeystoreError），不区分"口令错"与"密文坏"。
5. **丢失路径显式**。恢复码=与口令独立的第二因子；恢复码+口令双失=重新登记
   （链上旧承诺自然失效）；恢复码永不落服务器与 localStorage。

## 三、TCB 边界（诚实声明）

- JS 字符串不可强制清零——"内存即焚"是语义保证（无持久化），非物理擦除；
- localStorage 可被同源脚本/物理接触读取——密封后的密文无口令/恢复码不可解；
- 演示形态私钥加密强度以口令熵为下限；生产升级路径（WebCrypto 非导出/SE 芯片）
  见 docs/生产部署与安全演进.md。
