## 结论摘要

**裁决：NO-GO（维持不做；含「真 per-org 树」的单独立项——同为 NO-GO，见 §6）。**

三句话理由：

1. **二期①在当前部署形态下安全增益≈零**：电路 pk_RA 是装配期单钥常量锚（F9），一期 FedRegistry 全部机构的 ra 地址别名同一系统 RA 钥（chain_smoke.py:967/976/991 三域同址实锤）——「互认集成员证明」此时证明的是「pk_RA ∈ {pk_RA}」，空真集；它只在「各机构独立 RA 钥」的真实联邦部署下才有意义，而仓内不存在任何第三机构/独立运营方的需求信号。
2. **二期①不是「加一个成员证明」而是「拆除 F9 常量锚的 pk_RA 锚定结构重构」**：Z_A=SM3(…‖pk_RA.x‖pk_RA.y) 的常量折叠优化（装配期烧死 B₀/B₁ 两块）随 pk_RA 变量化整体失效，需电路内补 2 次 SM3 压缩+pk_RA 16 词格+apk 变基绑定+成员证明本体+实例面 26→27+，+3~5k 约束预估只对 Merkle 变体勉强成立、低估了结构性工程量，且触发指纹换代+黄金向量重生成+全量回归+第⑥次重部署仪式的全额换代级联——换来的是对现行真实缺口（§2.1 的授权面无域隔离等）零修复。
3. **二期②（真 per-org 树）与一期刚交付并实弹断言的任务书④语义直接冲突**：跨域吊销即时生效依赖共享单树（e2e_cross_org [Z] 实弹在案）；per-org 树在匿名证明（电路不披露签发机构）+单一 rev_root 实例（实例 23）的约束下，受理门无法一致地选根——要么回退跨域即时性（推翻已交付语义），要么升级为聚合根分层累加器（远超 +3~5k 的电路重造）。②不拆——它与①在同一需求信号（独立机构钥）下才成立。

**复评同时如实报出一期的真实安全缺口（不是背书过场，见 §2.1）**：跨机构吊销/恢复/签发授权面**无 org 域隔离**——任一机构管理员可吊销任意机构用户的任意凭证并推动全局共享树换纪元；该缺口是**应用层小修**（服务层加 org 校验），与电路无关，建议作为一期收尾硬化单独执行。

## 1. 信任模型现状审计（⑥一期落地后）

### 1.1 信任来源盘点

一期交付后，跨域出证/跨域吊销的信任链是：

```
AUTH 电路（pk_RA 装配期常量锚，F9）
  └─ 证明「THE 系统 RA（唯一一把钥）签发了该子凭证」
FedRegistry（⑥新增）
  ├─ orgs[orgId].ra 逐域推根钥校验（合约级 only-org-ra 负例在案）
  ├─ revAnchors：共享树根的「机构署名锚」（归因公示面）
  └─ globalRevRoot = keccak256(逐机构 orgId‖epoch‖root)（聚合承诺）
受理门（authz/service.py:276-278,313）
  └─ 实例 23（rev_root）== IdentityRegistry.revRoot（共享单树，唯一权威根）
```

关键事实：**受理门的撤销权威根只有共享单树一个**（authz/router.py:49-55 `_chain_rev_root` 只回读 IdentityRegistry.revRoot，FedRegistry 从不进受理判词）；FedRegistry 的机构锚与聚合根是**纯公示面**（e2e 离线 SM3 对拍+大屏展示），零消费方进安全判词。

### 1.2 「恶意机构能否污染他域吊销状态」——能，且在两层

**第一层（应用授权面，真实缺口）**：撤销/恢复/签发的 API 面无任何 org 域隔离——
- `POST /ra/revoke`（ra/router.py:483-504）与 `POST /ra/revoke/by-username`（:507-530）只有 `require_role("admin")` 角色守卫（accounts/deps.py:42-57 只查 role 不查 org），请求体与服务层（ra/service.py:478-503、:526-559，`_load_cred`:289-295 按 hash 直查）**均无 org 归属校验**：org-b 管理员可对 org-a 用户的任意凭证哈希签名吊销；
- 吊销执行体 `_revoke_credentials`（ra/service.py:563-667）**无条件推动共享树全局换纪元**（`set_revocation_root` :627）并写入全叶集——任一机构的这次越权吊销即时影响**所有域**的受理面（`stale_rev_root` 门控 409 强制全场刷新见证）；
- 恢复双控同构：任一 admin 可对任意 handle 发起恢复请求（:533-550），任一 auditor（跨域）可复核执行（:553-572）。

**第二层（链面锚，一期明知的口径）**：FedRegistry 合约的逐域钥校验（`require msg.sender == orgs[orgId].ra`，FedRegistry.sol:65）形态正确，但一期把**全部三个演示域的 ra 登记为同一把系统 RA 钥**（chain_smoke.py:967/976/991——org-a/org-b/org-c 的 registerOrg 实参同址，注释自认「一期=系统 RA 钥同构多域署名」）。于是：
- 「机构署名锚」**不是机构各自密钥的签名**，而是同一后端系统钥对任意 orgId 的代签——链面归因的权威只剩后端 DB 的 `users.org_id` 列（`_creds_org`，ra/service.py:415-421）；单一后端 RA 钥失陷=全部机构锚可伪造，链面无从分辨；
- `setOrgRevRoot` 对 root 值零校验（任意 32B 可锚，FedRegistry.sol:63-73）——一期因锚不进受理判词而只构成公示面污染风险，但它意味着**锚的语义安全完全寄生于「锚不被消费」这一现状**；
- 聚合根与共享树纪元的锁步不变式仅由测试/链烟断言维持（⑨站 172b924 §⑨-g「org 锚纪元永不超前共享树 revEpoch」），合约层面无绑定。

### 1.3 审计结论

一期的信任模型是**单运营方 + 行政分域**：密码学上仍只有一把 RA 钥、一棵树、一个受理权威；「多机构」是归因公示与演示语义，不是抗互不信任机构的隔离机制。§1.2 第一层缺口是真实且现网可触发的（越权吊销→全局换根），但它**不因二期①而闭合**（电路内成员证明管不着谁的 admin 会话能调哪个 API），也不因二期②而闭合（见 §6——per-org 树只收窄爆炸半径，授权面校验仍是应用层的事）。**该缺口的正确修法=服务层 org 隔离校验（一期收尾硬化），成本远低于二期任何一件。**

## 2. 二期增量真实性：「成员证明」还是「pk_RA 锚定结构重构」？

### 2.1 电路内 pk_RA 的真实锚定形态（逐锚核实）

- **pk_RA 以 Z_A 形态烧死**：Z_A = SM3(ENTLA‖ID_A‖a‖b‖Gx‖Gy‖pk_RA.x‖pk_RA.y)（GB/T 32918.2 §5.5，sm2_z_anchor.rs `z_u_preimage`）；210B 原像=常量前缀 146B+pk_RA 坐标 64B，因 pk_RA 装配期恒定 ⟹ **B₀/B₁ 两块全常量 ⟹ IV₂ 常量折叠**（决策 #23 注释，「M2c 签发者 Z_A 常量折叠同先例族」）——电路只装剩余块。
- **锚格**：Z_A 的 8 个折叠词以**单值列常量格**落位 RANK_ZA=51..58（sm2_full_statement_assemble.rs:105、:1075-1077 `emit_const_val`）——盲签草案 §1.2 F9 判词原文：「pk_RA 的 Z_A 是装配期常量锚——**即 pk_RA 被烧进电路 pin**」。
- **apk 路径同烧**：E10 的 apk=pk′+pk_RA staged 基头绑定（同文件 E10 段注释；witness 侧 sm2_auth_assemble.rs:130）依赖 pk_RA 常量性。
- **受理面配套**：`/ra/pubkey` 公开面出唯一 ra_pub_hex；受理门 F8 验签与实例钉（authz/service.py:290-313，实例数 `len(inst) < 26` 硬检）全按单钥建面。

### 2.2 拷问的答案：二期①=结构重构，「成员证明」只是其上的最后一小节

多机构场景下每机构有自己的 pk_RA ⟹ 前置工程=**把 pk_RA 从装配期常量改成语句变量**，这至少拆掉三样现役承重结构：

| 拆除项 | 现役形态 | 重构后 | 约束/工程量重估 |
|---|---|---|---|
| Z_A 常量折叠 | B₀/B₁ 折叠为 IV₂ 常量，电路只装 1 块级联 | pk_RA 64B 变量化 ⟹ 需电路内补 **2 次 SM3 压缩**（混合常量/变量词块） | 本架构 SM3 已查表化（sm3_compress_v2，RANK_BASE_V2=240 基址），全语句 e(3 块)+C(1)+SN(1) 预算约 2.9k ⟹ 单压缩数百约束量级，补 2 块约 **+1~2k** |
| pk_RA 词格 | 零词格（仅 8 个 Z_A 常量词） | pk_RA.x/y 16 词见证格+进 Z_A 原像消息词 | **+100~300** |
| apk staged 绑定 | 常量偏移点加形态 | pk_RA 变点 ⟹ 通用点加路径改接 | **+30~100**（EC 侧非大头） |
| **成员证明本体** | 无 | 二选一：**枚举表路线**（Σ sel_k·(pk_RA−pk_RA,k)=0，K 机构 K 组等值+bool）≈**可忽略**，但**每次新机构准入=改电路重编译**，联邦动态准入被焊死；**Merkle 路线**（org 集 SM3 树深度 3~5，路径电路内 2-并 1 哈希）≈**+1.5~4k**，且新增公开实例（org 集根，实例 26→27+，受理门 `_expect` 面+三值断言+实例数硬检全换代） | 二者必居其一，工程形态完全不同 |
| 受理门锚链 | pk_RA pin 自含（第三方凭 pin 即可复验） | 需在受理时点从 FedRegistry 链面读回 org 集根（§一期留的「二期=链面读回」欠账一并到期） | 非约束成本，但新增暴露面+新失败模式 |

**重估结论**：枚举表路线总计约 **+1.5~3k**（低于预估带下沿，但以「准入即重编译」为代价，运营上自败）；Merkle 路线总计约 **+2.5~6k**（+3~5k 预估带只对这个变体勉强成立且偏乐观）。**「+3~5k 约束」作为立项口径的问题不在数字精度，而在它把「叶子」（成员证明）标了价、把「根手术」（F9 常量锚拆除+Z_A 折叠失效+apk 改接+实例面换代+黄金向量全重生成）当成了免费前置**——后者才是本项目的承重墙：约束数叙事（19,434 同语句最优）、①站 D18 定谳、盲签 v2 设计（其裁决一明写「电路锚 pk_RA」为构造选型前提、「AUTH 电路零改动」为设计支柱）**全部踏在 F9 上**。二期①落地即推翻盲签草案 §5.2 的逐位核对表前提， queued 设计线连带返工。

### 2.3 增量真实性判词

在「单系统 RA 钥别名全机构」的现状下，成员证明的命题退化为「pk_RA ∈ {pk_RA}」——**逻辑恒真，密码学零内容**。二期①的完整价值只在「各机构独立 RA 钥+独立运营方」部署形态出现后才开始计息；该形态所需的不只是电路（还有各机构钥托管、逐域后端、跨域受理协议），电路只是其中最贵的一块前置。

## 5. 裁决

### 5.1 总裁决：**NO-GO**（多机构二期①②③全部维持不做）

1. **增益虚**（挂锚 §2.3/§3.2）：单系统 RA 钥别名全机构（chain_smoke.py:967/976/991）下成员证明命题恒真、零密码学内容；收益兑现前提「独立机构钥联邦」无任何在案需求信号。
2. **代价实且性质被低估**（挂锚 §2.2/§4）：二期①实质是拆除 F9 装配期常量锚的 pk_RA 锚定结构重构（Z_A 常量折叠失效+apk 改接+实例面换代），+3~5k 预估只覆盖叶子不覆盖根手术，且触发指纹/黄金向量/三值断言/全量回归/第⑥次重部署全额级联，并推翻盲签 v2 设计的裁决一前提造成 queued 线连带返工。
3. **②与已交付语义冲突**（挂锚 §1.1/§6）：跨域吊销即时生效是任务书④明文语义且已被一期实弹断言（e2e_cross_org [Z]），per-org 树在匿名证明+单 rev_root 实例约束下无法一致选根——独立实施=回退已交付属性或升级为远超预估的分层累加器电路重造。

### 5.2 重评触发信号（满足任一即重开评审，非自动 GO）

- **T1（需求信号）**：出现真实第三机构或独立运营方，且其要求**独立持有 RA 签发钥**（非共用后端行政分域）——以合同/立项文件为凭，非演示诉求。
- **T2（技术前置信号）**：盲签 v2 或任一 queued 线先行落地并要求多签发钥（使多钥电路成为其前置件，工程顺序倒置为合理）。
- **T3（威胁模型信号）**：出现「不信任受理门的第三方验证者」的真实验证场景（对外公示的可验证出证），使电路自证互认集成员成为必需项。
- **前置条件（任何触发下都必须先行）**：§1.2 授权面 org 隔离硬化完成——电路工作不修复应用层授权缺口，先电路后授权是倒序。

### 5.3 立即执行项（与裁决并行，非二期范围）

**一期收尾硬化**：ra 服务层对 revoke/revoke-by-username/restore-request/issue-sub-credential 补 org 归属校验（目标凭证归属域==操作者账户 org_id，跨域 403 fail-closed）+负例测试+e2e 断言。零电路、零合约、零换代；这是 §1.2 第一层真实缺口的唯一对症修法。

## 6. 「真 per-org 树」单独立项裁决

**裁决：NO-GO，与①绑定同一重评触发集（T1~T3）；不支持拆分单独实施。**

**可拆性事实**：②存在零电路实施路径——FedRegistry.revAnchors 已在链（⑥站已部署且服务面已接线推根），受理门把权威根从 IdentityRegistry.revRoot 换为「申请者会话 org 的链面锚」+撤销服务按域分树+见证分发按域，电路字节零动、指纹零换代。**技术上可拆。**

**但语义上不可独立成立**：

1. **回退已交付语义**：受理门按会话 org 选根 ⟹ 每域吊销只影响本域树 ⟹ 任务书④「跨域吊销即时生效」（一期 e2e [Z] 刚断言的能力）被静默推翻——二期把一期刚交付的明文需求做没了，不是增量是回退。
2. **匿名证明下的一致选根不可能**：电路不披露签发机构（D18 零身份），实例 23 只有一格——受理门无法从证明本身得知该钉哪棵树根；按会话 org 选根只是单运营方下的启发式（申请域==签发域），在真联邦形态（跨域申请）下断裂。要一致，要么电路披露 org（隐私语义降级），要么升级为聚合根分层累加器（实例 23=根之根，SMT 织入整体重造）——后者远超 +3~5k，属电路重造而非增改。
3. **零安全差**：当前全机构别名同一系统 RA 钥 ⟹ per-org 树只是同一写者的记账分册；§1.2 的真实污染路径（授权面无隔离）在 per-org 树下原样存在（越权吊销仍可把异域叶写进其目标域的树）。真正的隔离增益同样只在 T1 信号出现后计息。
4. **拆分的利弊账**：利=回避电路换代；弊=推翻已交付语义+全部根消费面改动（受理门/worker 见证新鲜度/e2e/链烟锁步断言）回归一轮+为①预埋的半成品结构在 T1 到来时仍要再动一遍。**弊大于利。**
