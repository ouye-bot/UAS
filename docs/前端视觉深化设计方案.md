# 前端视觉深化设计方案（2026-10-01 · 待队长批准后实施）

> 目标：交互感、动态感、高级感、粒子感并存，不花里胡哨，简约大气。
> 硬约束：**功能设计零变化**——业务逻辑/API 调用/交互流程/文案语义全部冻结，
> 只做视觉层加法。每批过 e2e 门禁（浏览器 29 断言天然守护冻结面）。

## 一、冻结面（先划红线——工程对设计的护栏）

e2e_browser_ui 29 断言实测依赖（scripts/e2e_browser_ui.py 盘点）：

1. **全部可见文本不可改不可删**（text= 定位：密码未达标/主凭证已签发/
   领取飞行令牌/可出证窗口/receipt_not_found/检查点锚定/协作台账/
   验证工具分发/政策/上限…）；
2. **结构契约**：`.stepper .step` 数量断言（审计台==4、飞行屏≥4）、
   `nav button:has-text(...)` 角色导航、`option` 计数、`type='password'`；
3. **标题**以"飞证"开头；**零 pageerror**；
4. 新增装饰性文本（如计时器）= 允许但最小化，且每批必跑 e2e 验证
   `count>0` 类断言不被新增节点干扰；
5. 装饰层一律 `aria-hidden` / `pointer-events:none`——不进无障碍树、
   不吃点击。

## 二、设计哲学

**一句话：低空空域的精密仪表盘**——像航空仪表与瑞士版式：冷白基底上
的分层玻璃、发丝线、等宽数据、微光信标；一切动效服务于"状态可感知"，
而不是"页面在表演"。

五个支柱（每条新效果先过这五关，过不了就不做）：

| 支柱 | 判据 |
|---|---|
| 层次 | 深度来自表面分层+定向阴影，不来自加颜色 |
| 精密 | 等宽数字/发丝线/角标刻度/8pt 节奏——细节密度=高级感 |
| 回应 | 任何交互 ≤200ms 内有可见反馈（亮度/位移/边框） |
| 生命 | 环境动效克制持续（粒子场+一个呼吸点=同屏上限 2 个） |
| 叙事 | 入场编排只引导一次视线（≤400ms），然后静止 |

领域意象翻译（含蓄到几乎不可察觉，但让系统"像自己"）：经纬网格
（坐标底纹）、信标脉冲（粒子偶发扩散环）、航迹（状态流光）、仪表框
（飞行屏四角刻度）。

## 三、视觉语言深化（基于现有 token，不换色系）

现状底子（淡雅端庄冷白 #f6f8fb+墨蓝+青蓝点缀+暖金辅色）保留——
竞赛演示环境多为投影，浅色系在弱投影上远比深色稳（备选否决记录见 §七）。

- **表面阶梯**：surface-0（页面）/ surface-1（卡片）/ surface-2（悬浮）/
  glass（顶栏）四级；每级 = 底色 + 1px 顶部内高光（rgba 白 0.55~0.7）+
  定向阴影——"玻璃层叠"质感，纯 box-shadow 实现，零 JS。
- **坐标底纹**：body 叠 32px 网格（repeating-linear-gradient，3.5% 不透明度）
  ——保留现有两团径向光晕；纯 CSS，零成本，"空域图"意象。
- **字体纪律**：全部数值面强制 `font-variant-numeric: tabular-nums`；
  标题字距 0.3px；数字+单位对（如 "4.1s"）单位降为 12px 弱色。
- **动效令牌补充**：--t-slow: 360ms（仅路由过渡与 hero 入场）；
  入场统一 ≤400ms；缓动沿用现有 --ease。

## 四、七大升级面（每项：现状 → 改法 → 规格 → 风险）

### A. 设计令牌与地基层（全局质感一次跃升，零 JS）

- tokens.css 补 surface 阶梯/顶部内高光/--t-slow/滚动条与选区样式
  （细圆角滚动条 ink-3@30%；选区 accent-soft）。
- .panel 精密化：hover 由"仅阴影加深"升级为 **translateY(-1px)+边框
  微亮+阴影加深**三联动；关键面板（hero/证书卡）加 **8px L 形角标刻度**
  （::before/::after，35% 不透明度——仪表取景框意象）。
- 风险：纯 CSS 增量；`.stepper .step`/文本零触碰。

### B. 粒子场 2.0「信标场」（粒子感的主表达）

ParticleField 升级（仍单 canvas、零依赖、种子化随机纪律不变）：

- **三层视差**：远/中/近三层（合计 ≤56 粒），近层稍大稍亮漂速稍快；
  鼠标移动时层间位移差（transform 于层组，非逐粒子重算）——"深度"而非"热闹"。
- **信标脉冲**：粒子偶发一次扩散环（同屏至多 1 个，8s 节奏，青/金双色
  沿用）——传感器信标意象，是"系统活着"的呼吸。
- **节点十字**：~6% 粒子画为 3px 十字微标（测量控制点意象）。
- **推广到门户与飞手首页**（LoginView/RecordView 接入——现状仅审计台/
  机构台有）：门户=第一印象，四点同语言。
- 性能与纪律：devicePixelRatio 封顶 2；document.hidden 暂停 rAF；
  prefers-reduced-motion=静态单帧；单帧预算 <1.5ms。
- 风险：LoginView 增加一个绝对定位 canvas（aria-hidden）——不碰任何
  文本节点；e2e 门户段走查复跑守护。

### C. 微交互体系（交互感的核心）

- **按钮**：hover 加背景渐变位移（background-position 200ms，光从上掠过
  的暗示）；busy 态配现有 .spin（不改按钮文案——busy 文案是既有动态行为）。
- **输入**：无效提交一次性 shake（180ms，translateX ±3px）+红边——
  只加 class 与 animation，不动 v-model/校验逻辑。
- **导航**：滚动 >8px 时顶栏浮现底阴影（ScrollListener 20 行）；active
  指示条加 200ms 宽度入场。
- **表格行**：hover 背景 2% 墨色+过渡。
- **KPI 数字**：挂载时 count-up（一次性 320ms，reduced-motion 直显）；
  轮询数值变化时 80ms 背景闪脉冲（key 变化触发）。
- **状态徽章**：进行中态（待批准/已批准·待执行）加 2px 状态点呼吸
  （fz-pulse 复用）；终态静态——"活着的才呼吸"。
- **状态卡流光**：req-card 左侧色条升级渐变光轨，状态变化时一次 400ms
  流光扫过（class 一次性添加）。
- 风险：`.stepper .step` 内部只加装饰 span；徽章文本不动。

### D. 页面编排层（动态感的克制表达）

- **路由过渡**：router-view 包 `<Transition name="page">`——淡入+上移
  8px/180ms（已按 fullPath keyed，包装零逻辑改动）。
- **列表 stagger**：收件箱/待批卡依次入场（nth-child animation-delay
  30ms 递增，封顶 8 张）——纯 CSS。
- **刷新脉冲**：4~5s 轮询数据更新瞬间容器 80ms 微亮（watch+class 切换），
  让"自动刷新"被感知而不打扰。
- **申请六段进度仪表化**（演示核心屏——评委盯着最久的 2 分钟）：
  段状态三态（待办=暗/进行=呼吸+左轨高亮/完成=✓ 刻画入场）+段间连接线
  随进度点亮；新增装饰性"已耗时"微计时（12px 弱色，右下角）。
- 风险：新增装饰文本 1 处（计时）——e2e 复跑验证不干扰 count 断言。

### E. 飞行屏与数据可视化（包框与曲线精修，3D 逻辑零触碰）

- **仪表框**：3D canvas 外包一层 CSS 框——发丝边+四角刻度+内 vignette
  （2% 暗角）——"取景器"感，FlightGlobe 内部一行不改。
- **高度曲线**：线条 drop-shadow 1px 发光+当前点脉冲；网格 8% 透明度。
- **仪表数字**：tabular-nums+单位小字对齐。
- **证书卡**：verdict OK 时一次性金环光晕扩散（300ms）+卡片微升——
  "盖章"瞬间的仪式感。
- 风险：全部作用于既有元素的 CSS 层；`.stepper .step` 计数不变。

### F. 空态与细节收口（最后一公里）

- 空态（"尚无出函记录"等 note 上方）加 24px 线性图标（描边风格与顶栏
  icon 同语言，aria-hidden）。
- kv 表 dt 右对齐微调；分隔线 40% 透明度统一。

### G. 无障碍与降级（不可妥协项）

- prefers-reduced-motion：全局已有 0.01ms 降级，粒子场静态帧——延续。
- 焦点可见性（R3-C2 已有）不回退；装饰层全部 aria-hidden。
- 色彩无新增色相：一切新效果=现有 token 色相 × 透明度分层。

## 五、负面清单（"不花里胡哨"的硬约束）

不做：彩色渐变大按钮 / 大面积光晕 / 视差滚动劫持 / 自定义光标 / 音效 /
emoji 装饰 / 循环文本动画 / >400ms 入场 / 同屏 >2 个持续动画 /
任何文案-DOM 语义-业务逻辑改动 / 任何新运行时依赖（不引动画库——
纯 CSS+canvas，构建 gzip 增量预算 <25KB）。

## 七、备选方案否决记录（评委视角拍板）

1. **深色"指挥中心"主题**——否决：竞赛演示常在投影环境，深色在弱投影
  上发灰失真；浅色"晨雾白+精密仪表"更贴政务/司法语境；且深色需全视图
  硬编码色普查（fz-badge 等含裸色值），赛前风险不成比例。可作竞赛后
  可选主题化演进。
2. **引入动画库（GSAP/framer-motion 类）**——否决：违背零依赖纪律，
  现有 CSS+canvas 能力全覆盖需求。
3. **星座连线粒子/鼠标跟随光斑**——否决：粒子间连线与光斑跟随在
  数据密集页抢注意力，违反"同屏 ≤2 个持续动画"上限。
