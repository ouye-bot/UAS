# 飞证系统三代理 R4 复验轮 · 合成总评与整改规划（2026-09-26）

> 评审主体：三个干净上下文子代理（A 密码安全与性能 / B 业务工程与落地 / C 功能贴合与前端设计），只读深读+只读探针，全部发现带 file:line 证据。分报告同目录 A/B/C 三份。上一轮评审（2026-09-24）之 R3-0~R3-4/R3-3.1 整改经本轮逐项抽查**基本真实落地且质量合格**（B 席核验矩阵 14 行），本轮净新增 3 个 P0 级、4 个 P1 级发现。

## 一、本轮最重要发现（多席交叉印证）

1. **🔴 P0·TRAIL 合规证书对恶意出证方数学空转**（A 席）：alt_max/t_start 由证明者自报且只烧进约束常量、不入公开实例与验证绑定——飞过限高者可自报 alt_max=655m 对真实链头出 verify-OK 的"合规证书"，第三方无法分辨。这是继 AUTH SMT 撤销空洞（R2）、撤销键域（R3-0）之后**第三次"空转谓词"接缝病灶**，且五个 TRAIL 负例全用固定 alt_max 构造（盲区同型）。修法：alt_max/t_start 提升为公开实例钉（+2 约束）+verify_instances 对拍+负例补"抬上限"形态+黄金向量 v5+repin。1 人天。
2. **🔴 P1·政策公示对拍门控死码**（B 席）：R3-1.3 把门控属性从 bool 换成 lambda，但门控仍按 `is False` 比对——**政策对拍 fail-closed 防线静默失效**，红队记录对应证据随之失效。修法 0.5h+门控级测试。
3. **🔴 P0/P1·TrailView 导出件与真出证数据面两套口径**（B+C 双席独立印证）：导出 JSON（绝对秒 t+锚链头）按真管线契约 zkc 必拒"换链头"；证书卡复验命令引用不存在的 expected.json；instances.json 服务端支持却无下载按钮；"授权编号"输入框是装饰占位。修法 3~4h。
4. **P1·RA 演示钥未随机化**（A 席，缓解不对称新发现）：demo_up 只随机化了 ENGINE，RA 仍是公开可推算——评委可自推 RA 钥伪造子凭证直通全链。修法：demo_up 注入随机 FZ_RA_SK，0.5 天。
5. **P1·撤销端到端负例缺失**（A+B 双席）：R3-0.4 承诺的"吊销后旧子凭证必拒入 check.sh"未交付，演示库 revocations=0——B4 宣称验证深度停在单测层。0.5 天。
