# 账户门户与三角色工作台 · 设计方案（2026-09-29）

> 队长设想：整体系统前加一道登录/注册门户；飞手自助注册→补资料→签发；审计员、
> 机构管理员以账户登录协同工作；操作令牌不再外露粘贴，权限随账户会话流转。
> 本文档为思考优化后的完整设计。**全部未实施。**

## 0. 意图提炼（队长要解决的三件事）

1. **一个前门**：登录/注册后按角色进入各自工作台，职责一眼清晰——飞手看不到
   审计与机构的功能面，反之亦然。
2. **口令令牌退役**：审计令牌、RA 操作员令牌不再以粘贴/%TEMP% 文件方式外露，
   权限绑定账户会话；"口令一直在外暴露"的安全感问题根除。
3. **双控成为系统内工作流**：审计员立案发协同请求 → 机构管理员看到"为什么"
   （依据+理由）→ 点击批准 → 系统自动完成协助解锁并回流回执。

**不变项（重要）**：飞行与密码内核零改动——RA 签发、AUTH 零知识证明、一次性
飞行令牌、遥测链、TRAIL 出证、链锚定、桥接引擎全部原样。本设计只重做
"谁在操作"的入口层，不碰"授权什么"的密码层。

## 1. 总体形态

```
                 ┌──────────────────────────────────┐
                 │     门户：登录 / 注册（唯一前门）   │
                 │   用户名+口令 → SM2 挑战-应答认证   │
                 └───────┬──────────┬──────────┬────┘
                    角色=飞手    角色=审计员   角色=机构管理员
              ┌──────────▼───┐ ┌────▼─────────┐ ┌▼──────────────┐
              │  飞手工作台   │ │   审计台      │ │   机构台       │
              │ 资料/申请令牌 │ │ 案件收件箱    │ │ 待批协作请求    │
              │ 飞行/出证     │ │ 卷宗/立案     │ │ （依据+理由全文）│
              │ 留痕/公开核验 │ │ 发协同请求    │ │ 批准→自动执行   │
              └──────┬───────┘ └────┬─────────┘ │ 签发台账/吊销   │
                     │              │           └───────┬───────┘
                     │        协作请求队列（服务器，双签名）│
                     └────────── FZC2 双签信封 ──────────┘
        密码内核不动：RA签发 / AUTH电路 / 飞行令牌 / 遥测链 / TRAIL / 链锚定
```

## 2. 账户与密钥：账户 ≠ 凭证（核心原则）

### 2.1 三条铁律

- **口令只做一件事：解封私钥**（KEK）。服务端永远不见口令明文、不存口令哈希、
  不见私钥明文。
- **登录 ≠ 能飞**。登录只是"拿到自己的钥匙"；起飞授权仍走子凭证 + AUTH 零知识
  证明 + 一次性飞行令牌，与今天完全一致。
- **账户是系统面，凭证是链上面**。改口令不动链；吊销凭证不删账户；两套生命周期
  彻底解耦——这正是当前"本机 keystore"模型做不到的跨设备与可管理性。

### 2.2 注册/登录时序——公私钥生成与上链注册的时点（队长之问）

**注册（飞手，三步向导）：**

| 步 | 动作 | 密码学事实 |
|---|---|---|
| ① 建账户 | 用户名+口令（强度提示）→ **浏览器内生成 SM2 钥对** → 展示公钥指纹（SM3 前 16 字节，供用户核对）→ KDF(口令,salt) 派生 KEK → SM4-GCM 密封私钥（AAD=用户名‖公钥）→ 上传 {用户名, 角色=飞手, salt, 公钥, 密封钥} | 服务端只拿到密封件；账户建立（状态=待完善资料） |
| ② 补资料 | 实名信息 + 无人机序列号/型号 + 限高申请 | 纯资料，无密码动作 |
| ③ 签发上链（自动） | RA 签子凭证（绑定身份+无人机+限高）→ **凭证哈希写入吊销累积器（SMT）→ 链锚定留痕** | 凭证生效，进入工作台 |

**直接回答时点问题**：公私钥生成 = 第①步、浏览器内、毫秒级；**上链注册 =
第③步 RA 签发子凭证时**（凭证哈希进累积器 + 链锚定）。账户创建本身不上链
——链上存的是密码学承诺（公钥/凭证哈希），不是用户名口令。

**登录（任意设备）：**

```
输用户名+口令 → 取回 {salt, 密封钥} → 本地 KDF 解封
  （解封失败 = AEAD 认证标签不符 = 口令错，无需服务器判）
→ 解封钥与服务器登记公钥比对（密钥核对）
→ 用钥签服务器一次性 nonce → 验签通过 → 发会话 Cookie（HttpOnly）
→ 按角色进入工作台
```

要点：**系统自身登录认证用的是国密 SM2 挑战-应答签名，而不是口令哈希比对**
——数据库里根本没有可以"撞库"的东西。本机账号检测（localStorage keystore 探测）
按队长要求移除；密封钥存服务器侧，换设备登录天然成立，原"信封导出导入"的
跨设备诉求被服务器存储取代。

### 2.3 预置机构账户的首登激活

审计员/管理员账户由引导脚本预置 {用户名, 角色, 初始口令 KDF 验证子}。首次
登录用验证子核对后**强制激活**：浏览器当场生成钥对+密封上传，随后删除验证子
——之后进入纯挑战-应答态。队长拿到的是"账户+初始口令"，系统拿到的是
"无口令存储+可追责签名钥"。

### 2.4 服务端可见性（威胁模型，写进口径卡）

| | |
|---|---|
| 服务端存 | 用户名、角色、salt、公钥、密封私钥、资料、会话表 |
| 服务端不见 | 口令（明文+哈希都没有）、私钥明文 |
| DB 泄露后果 | 可对密封件离线猜口令（KDF 21000 拉高成本）——诚实边界；演进项：OPAQUE/PAKE 消除离线面 |
| 会话 | HttpOnly Cookie + 服务端会话表 + /auth/* 限速（复用现有限速器） |

刷新页面后会话仍在、但钥已锁——敏感操作前重新输口令解封（钱包式交互）。
不把明文钥放 sessionStorage（A-P1-2 纪律延续）。

## 3. 令牌退役映射

| 旧机制 | 去向 |
|---|---|
| 审计台演示令牌（/audit/demo-token、粘贴输入框） | 审计员账户会话（X-Audit-Token 头退役） |
| FZ_RA_OPS_TOKEN（%TEMP% 文件、ops-token-hint、RA 窗粘贴） | 机构管理员账户会话 |
| **一次性飞行令牌（AUTH 零知识绑定）** | **保留**——它是飞行许可（凭证据+限高签发、单次消费），不是"操作口令"，外露无害且本就该随人走 |
| 本机 keystore 检测（fzCred 本地键守卫） | 移除 → 服务器密封钥 + 会话守卫 |

## 4. 双控工作流：从流程约束到密码学强制

现状痛点：函件两窗粘贴；三模块评审 F-③⑤ 已定谳"双控目前是流程性而非范围
受限"（一函可解多令状、无令状一致性校验）。账户化正好把这一硬伤修成亮点：

1. **审计员立案**：填立案依据原文+调查理由（原文随案卷留存——顺手修掉
   F-③"依据哈希后即丢弃"），审计员 SM2 钥签名。
2. **发起协同解锁**：填目标实名/范围/时效 → 审计员钥签 (请求哈希‖令状哈希‖
   范围‖时效) → 请求入服务器队列（状态=待批）。
3. **管理员看全貌**：机构台展示依据原文、理由、目标、范围、时效、审计员
   签名指纹——"明白为什么"有了实物载体。
4. **批准**：管理员钥签**同一请求哈希** → 双签名齐。
5. **自动执行**：服务器组装 FZC2 信封（AAD 绑定双签+令状+范围+时效，单次
   有效）→ RA 侧解锁实名 → 回执自动回流审计卷宗。
6. **台账三笔**：发函/批准/执行各带操作者签名指纹，可追责到人。
7. **驳回路径**：管理员填理由驳回 → 请求终态，审计台可见（自然业务动作，
   非工程按钮）。

本质：**审计员钥与管理员钥缺一不可**——任何单一角色（包括服务器自身被完全
攻陷的场景下没有两把钥时）都无法合法完成解锁；范围/时效进 AAD，超范围即
验签失败。双控从"约定"升格为"密码学事实"。

## 5. 三角色页面清单

| 角色 | 可见 | 不可见（导航不渲染 + 服务端 403 双层） |
|---|---|---|
| 飞手 | 资料向导、起飞申请、令牌与飞行、TRAIL 出证、我的记录、回执查询、链上留痕 | 审计台、机构台、他人案件、任何 RA/审计管理端点 |
| 审计员 | 案件收件箱、卷宗、立案、协同请求、台账、链上留痕（公开面） | 飞手工作台、RA 签发操作 |
| 机构管理员 | 待批协作、签发台账、凭证吊销、账户重置 | 飞手工作台、审计立案（只能批不能替审计发函） |

## 6. 工程落点

- **后端**：新增 `app/accounts`（表：accounts / sessions / collab_requests /
  approval_ledger）+ `/auth/*` 路由（challenge/login/logout/me）+ 角色依赖注入
  （`require_role("auditor")` 等）替换现有 token 依赖；RA 的 revoke/collab 端点、
  audit 管理端点改挂角色依赖。
- **前端**：LoginView 重写为门户（登录+注册向导）；router.ts 守卫从 `fzCred`
  改为会话+角色；机构台 AdminView 新增；审计台（现有 v3 静态页）去令牌化改
  会话认证。
- **复用成熟件**：keystore.ts 的 KDF/密封格式（AAD 结构微调）、限速器、台账、
  FZC2 信封组装与验签——不新造密码原语。
- **不动**：bridge/prover/fence/authz 密码核心、RA 签发逻辑、链锚定、TRAIL。
- **测试**：单测（注册/登录/错口令/越权 403/双控缺一签名拒斥/过期/单次性）+
  e2e 浏览器回归改写（登录态 fixtures，29 断言全量重排）+ 手测清单重写。
- **纪律**：预置账户初始口令由部署脚本随机生成 → 环境变量/私下交付，
  **绝不入库、绝不入文档**（延续现行纪律）。

|---|---|---|
| 1 | 账户与门户：accounts 后端+挑战登录+会话+门户 LoginView+角色路由 | 1 天 |
| 2 | 飞手向导与隔离：资料表单+自动签发上链+去本机检测+去审计入口 | 0.5-1 天 |
| 3 | 双控工作流：请求队列+双签 FZC2+机构台+自动执行+台账+驳回 | 1-1.5 天 |

合计 3-4 天。时间紧的裁剪序：1 → 3 → 2 → 4（先账户+双控；第 2 批资料向导可
先做单表单简化版，向导分步后补）。

## 8. 收益与代价（自我批判）

**收益**：① 口令不外露（队长核心痛点根除）；② 双控密码学强制（把已知评审
硬伤 F-③⑤ 修成亮点）；③ 职责清晰 + 答辩叙事升级——"我们连自己的登录都
不存口令，认证靠国密挑战-应答签名"；④ 顺手修掉 F-③ 立案依据丢弃、A-P1-2
会话钥边界两个已知项。

**代价/边界**：① 密封钥上服务器 → DB 泄露可离线猜口令（KDF 缓解+OPAQUE
演进，写进口径）；② 刷新后敏感操作需重新输口令（钱包式，安全叙事优先）；
③ 口令丢失 = 钥不可恢复 = 凭证需重发（私钥不出端的注脚，正面叙事）；
④ e2e 与文档联动成本不小（已计入第 4 批）。

## 9. 待队长拍板

1. **凭证签发要不要过管理员审批队列？** 推荐：不过——"例行自动化、例外
   双控"叙事（签发规则明确自动执行，人工介入留给解锁实名这类例外权力）。
2. **刷新后重新解锁密钥**（输口令）：接受（推荐）vs sessionStorage 缓存钥
   （不推荐，违背既定纪律）。
3. **审计台形态**：session 化现有静态页（推荐，改动小）vs 并入 Vue 单页。
4. **旧 keystore 导出导入功能**：下线（推荐——服务器密封钥即跨设备）vs 保留
   为可选备份。
