## 三、问题清单

### P0（必须修——阻断演示/伤害可信度）

**P0-1 TRAIL 判决件/下载 URL 缺 `/prove` 前缀——证书卡永远渲染不出**
- 证据：桥端路由 `router = APIRouter(prefix="/prove")`（gcs/bridge/prover.py:26）+ `@router.get("/case/{case_id}/{artifact}")`（prover.py:554），实际路径=`/prove/case/...`；而 TrailView 判决件拉取 `fetch(${bridgeBase()}/case/${caseId}/verdict.json)`（gcs/web/src/views/TrailView.vue:79）与五件下载 `dlUrl()`（TrailView.vue:139）均用 `/case/...`。对照组：ChainView 用的是正确的 `/prove/case/`（ChainView.vue:126），e2e 脚本也用 `/prove/case/`（backend/scripts/e2e_frontend_api.py:297）——所以 API 级 47 断言全绿而 UI 面断裂。
- 影响：出证 60 秒跑完后 `fetchVerdict` 五轮 404→cert 恒 null，用户只看到“判决件暂不可读”+一个同样 404 的“重新获取”按钮（TrailView.vue:178-182）。主线“④留痕与 TRAIL→第三方复验”整个压轴环节断掉，且“重新获取（无需重新出证）”的救济设计反而放大困惑。
- 改法：TrailView.vue:79/139 两处补 `/prove` 前缀（与 ChainView 单源化一个 `caseUrl` 工具函数）；补一条浏览器级（或至少对 dlUrl/fetchVerdict 字符串的 vitest）回归，终结“e2e 双形态兼容掩盖 UI 缺陷”的复发。

**P0-2 链上留痕“本机复验材料区”在正常主线上不可达**
- 证据：`localCaseFor()` 依赖 `sessionStorage fzApplyFlow.case_id`（ChainView.vue:101-111），但申请流程 ready 时即 `clearFlow()`（ApplyView.vue:294）——正常走完申请后快照已删。
- 影响：飞手走完全流程再看自己的授权记录，永远命中“完整证明文件存放于出证设备本机”的降级文案，W-8 交付的“本机当次授权五件材料下载+复验命令”在演示主线上无法展示；手测清单⑥承诺直接落空。
- 改法：case_id 落入身份域 localStorage 键（并入 material.ts:61-65 的 IDENTITY_SCOPED_KEYS 清扫清单），localCaseFor 改读持久键；或 /chain/record 端点补返 case_id。

### P1（应该修）

**P1-1 取件“字段校验通过”标签部分虚标**：`checkTokenFields(p.tok, p.tok.plan_hash, ...)` 把令牌的 plan_hash 与它自身比较（FlightView.vue:123；token.ts:92），“plan_hash 与本机计划不一致”永不触发。桥端 /arm 有权威五查兜底，但浏览器侧展示了一个没真正执行的校验结论。改法：改传 `fzLastPlanCommit`（ApplyView.vue:343 已落盘）比对，令“校验通过”名副其实。

**P1-2 会话私钥明文平铺在可编辑输入框**（FlightView.vue:485）：与“身份不出设备”叙事自相矛盾，评委俯屏即见私钥明文，且可被误编辑导致解密失败。改法：type=password+自动注入，或整字段隐藏仅留“会话钥已在本机（关浏览器即焚）”说明。

**P1-3 登记确认后主线程假死数秒**：sealKeystore 双 KEK = 2×21000 轮 SM3 全同步执行（LoginView.vue:153；keystore.ts:13 注释自估约 3.5s/次），点击“确认登记”后 busy 状态因 JS 阻塞无法渲染，观感即卡死。改法：按钮点击先渲染“正在加密本机密钥（约数秒）…”再 setTimeout 执行；ApplyView 解锁同理（ApplyView.vue:148）。

**P1-4 TrailView“授权编号（登记绑定）”标注错误+默认值"1"**（TrailView.vue:13、154-156）：该值实为飞行授权编号（取件令牌 authId），与登记无关；新用户未飞过即显示"1"误导。改法：缺省显示"—"，标注改“飞行授权编号（取件后自动带出）”。

**P1-5 第三方复验指引与 expected 单源自相矛盾**（TrailView.vue:211-212）：指引①让用户“将本段链头写入 expected.json”，但 W-8 后 expected.json 已是直接下载件（单源=验证时真实消费的绑定，ChainView.vue:113-123 注释自证）。评委会照指示手工编辑一个不需要编辑的文件。改法：改“expected.json 即右侧下载件（已含本段链头），两步命令可直接执行”。
