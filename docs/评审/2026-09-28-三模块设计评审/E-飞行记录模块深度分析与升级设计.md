# ③「令牌与飞行」飞行记录模块深度分析与升级设计（2026-09-28，只读评审+设计方案）

**红线声明**：本方案全部改动限于 UI 呈现层与旁路显示字段（att/mode/fc_armed/n 等），不触碰 14B 链行、检查点语义、围栏参数写入序、令牌五查。唯一涉及桥的项（补发 `/telemetry/event`）调用的是既有端点与桥已生成的事件对象，属补全既有设计生命周期，非链语义变更。

## 一、“粗糙模糊”缺陷清单（队长原话的具体化）

队长的“起飞过程不知道在干什么”可拆为五组、15 条可修缺陷：

**A 组：流程不显性——四步流程藏在一句话里**
1. 整个飞行流程的操作指引是一段 128 字散文（①开始记录→②爬升→③采满出证→④封链，FlightView.vue:543）。界面本身没有步骤结构：三个 panel（领取/解锁/记录）平铺长页，飞行中控制按钮在折叠线以下，飞手须滚动才能点到“悬停/封链”。GCS 反模式：控制面必须常驻可视。
2. “解锁起飞”与“开始记录”的两步语义（授权门≠证据链）只靠散文解释。ARM 成功后没有“下一步”引导——横幅变 ARMED（:523）后主 CTA 仍视觉不变，用户不知道现在该点“开始记录”。
3. “开始记录”按钮未 ARM 时可点（:590 仅 `:disabled="!!chain"`），点击后被桥拒绝才弹“请先解锁起飞”（:180-184）——用错误驱动而非状态驱动的流程表达；且它用 ghost 次要样式，与“结束飞行并封链”的主按钮样式（:597）权重倒挂。
4. ARM 期间无进度反馈：`busy` 只禁按钮（:528），但桥内 connect 失败重试 30×2s（sitl_link.py:59-104）、set_param 确认环最长 12s——按钮文案不变（无“解锁中…”），观感即卡死（与 A 席 P1-3 登记假死同型）。

**B 组：“点数记录”概念不可见、不可懂、无进度感**
5. 采样进度以三种碎片形态散落：右列小注“采满 47/128 点后…”（:586）、底部另一条小注（:600）、KV 表“已采样本 47”（:605）。没有进度条、没有倒计时（128 点@2Hz=64 秒这个“还需 41 秒”的关键预期从不出现）、没有解释“点”是什么。
6. 更深的语义缺失：128 点不是普通进度，是 **TRAIL 合规窗口**（前 128 样本=出证窗口，S1 编舞“一飞到底”实锤）。若窗口内发生超限，证书出不来——UI 完全没有表达这一点，也没有“先合规 64 秒、再演示冲高”的顺序引导。队长的演示动线（合规出证+冲高取证）全靠口头记忆。
7. “检查点”概念零用户化：只有一条静态注“检查点已生成（60s 节奏）——链头经设备钥签名后锚定上链”（:608）。这本是飞行中最强的安心点（“每 60 秒你的证据已固化上链一次”），被埋没。

**C 组：按钮可用/禁用不自解释、操作风险**
8. 控制按钮分裂在两处：「自动飞到目标高度/停止自动」在 grid2 右列（:582-585），「开始记录/手动爬升/悬停/结束飞行并封链」在另一行（:589-598），中间隔着 canvas。且门控规则互相矛盾：自动飞行要求 `chain`，手动爬升/悬停只要求 `armed`，开始记录什么都不要求——三套规则无任何解释。
9. “结束飞行并封链”紧邻“悬停”，一击即 DISARM+锚定+不可逆（:255-271），无二次确认、误触即终结飞行。封链后按钮变“已封链 ✓”但仍可点击（chain 未清空，:590 的 disabled 恒 false），重复点击会重复 anchor+disarm。
10. **封链后无法开始第二架次**：`startChain` 被 `!!chain` 永久禁用，`endFlight` 从不清 `chain`（:167-202/:255-271）——换新令牌再飞必须整页刷新。多架次是演示日常（令牌一次性），这是硬工作流缺口。
11. 目标高度输入可键入超围栏值（:581 仅 input min/max 提示），实际执行被钳到围栏-3m（:278/:451）——用户键入 100、飞机到 27，无任何就地反馈。

**D 组：信息过载与重复**
12. 当前高度同屏出现≥4 处（仪表高度带、2D 高度曲线、底注：600、3D 隐含），围栏值≥4 处（横幅：523、高度带、曲线虚线：366-370、底注）。2D 俯视航迹在 SITL 原地飞行场景恒为一个点（A 席 §四.2 已判），四套可视化同屏且单列堆叠：仪表→3D(340px)→曲线→grid2→按钮→KV→时间线→记录单（:544-647），3D 作为主打视区反而被压到 340px。
13. 事件时间线用 KV 列表渲染在面板最底部（:611-624），飞行中最高价值的信息流（起飞/锚定/围栏红事件）被埋在链 KV 表之下，无自动滚动、无新事件高亮。

**E 组：状态断层与宣称矛盾**
14. **超限事件在 UI 路径不上链**：桥在 sitl_sample 响应里已生成 `event`（server.py:137-139，fence.py:67-75），但前端从不调用 `/telemetry/event`（grep web/src 零命中）；而告警条宣称“超限事件将随检查点锚定上链取证”（FlightView.vue:551）——检查点锚定只锚检查点（server.py:225-253），事件上链是独立端点。宣称-实现断裂，且恰在“围栏触发”这一演示高光时刻。S1 脚本（scenario_S1 §4）是调了 event 的，浏览器路径漏了。
15. 采样中断静默：采样循环对 `ok:false`（telemetry_timeout，server.py:127-128）与异常全部静默吞（FlightView.vue:209-211）——中途流死时点数停止增长，用户只看到“不动了”，与队长的“不知道在干什么”直接相关。另：非 STABILIZE/ALT_HOLD 黄条文案“油门指令不生效”（:558）在 280c09f 后已不准确（climb 会自动切 ALT_HOLD，server.py:306-310）。

（既有已修项不重复：3D 黑屏 NaN、悬停落地、TRAIL /prove 前缀、fc 上锁横幅等已闭环；A 席 P1-1 checkTokenFields 虚标、P1-2 会话钥明文（FlightView.vue:485）维持其待排期结论，本方案不展开。）

## 三、“点数记录”用户化表达方案

**命名换代：「采样点数」→「合规记录窗口」**。右侧栏新卡片（新组件 FlightProgressCard）：
- 主行：`合规记录 47/128 点`+环形进度（3D 左上 HUD 同步一个 44px 小环）。
- 副行（动态）：进行中=“约还需 41 秒（每 0.5 秒记录一点）”；已满=“✔ 已满 128 点——可生成合规证书 [前往生成]”（链内跳转④）；窗口内超限=红色“记录窗口内出现超限样本——本窗口证书将不可生成”（诚实暴露，这正是 B 组 6 的引导缺口）。
- 释疑行（hover/问号）：“点=每 0.5 秒存入飞行链的一次高度与位置记录；前 128 点（64 秒）构成可出证的合规窗口。”
- 检查点行：`已锚定上链 2 次（每 60 秒一次）`——把缺陷 7 转为安心点。
- 禁用期（S0-S2）：卡片灰态显示“0/128——解锁并开始记录后累积”。

## 四、3D 优化专项清单（低成本高观感优先）

**P0 观感救火（1 天内）**
1. 围栏柱超限转红：材质在 watch(fenceBreached) 中更新（当前构建时固化，FlightGlobe.vue:137-159/:210-217；A 席 P2 同判）。

5. 检查点锚定瞬间：无人机绿色脉冲光环一次（事件可视化，呼应 §三）。

**P1 结构升级**
6. 目标高度指示：半透明虚线圆环面在 targetAlt 高度（自动飞行时可见“正在追的线”）。
