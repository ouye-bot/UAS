## 1. 这是什么系统

飞证是一套面向**低空经济场景**的无人机合规飞行系统：飞手向系统提交起飞申请时，用**零知识证明**证明"我有实名登记凭证、我有相应操作资质、我的无人机已绑定、申请高度不超该机型法规上限"——而**不提交身份证号和任何属性明细**。系统自动核验通过后签发**签名授权令牌**，无人机只有拿到有效令牌才能解锁启动，且飞行高度被固件围栏硬性限制；全程飞行留痕锚定上链，一旦发生事故或超限，**凭审计令状可以追溯到具体个人**——但除此之外，任何人（包括平台运营方自己）都看不到"谁在飞、在哪飞、飞了多高"。

参赛定位：全国密码技术竞赛软件系统作品，密码技术三支柱=**国密算法（SM2/SM3/SM4）+ 零知识证明 + 联盟链**。

## 2. 要解决的三个真实痛点

这三个痛点是全部设计的总动因，也垫底了答辩时"需求真实性"的质询：

1. **Remote ID 广播与隐私的法定张力。** GB 42590-2023 强制无人机广播自身 ID 和位置，广播信号**任何人都能接收**——追踪者、偷拍者可借此定位"谁在拍什么"。国际上（美国 FAA Remote ID）对此有同样的公开争论。飞证的回答：合规所需的"可追溯性"不必建立在"人人可见"上。
2. **轨迹敏感性。** 航拍轨迹=家庭位置+拍摄对象+生活规律。现有平台把全体飞手的申请与飞行数据聚合成中心数据库，一次拖库就是全员移动画像泄露。
3. **最小必要原则的反面现状。** 现行模式里，每次飞行申请都要向平台交明文身份+计划；《个人信息保护法》的最小必要原则要求"达到目的所需的最少数据"——核验"是否合规"只需要一个**结论**，不需要数据本体。

**叙事红线（全体队友答辩时必须统一口径）**：飞证的隐私保护对象是"平台运营方与公众的过度收集"，**不是对抗监管**。实名制是法定义务，系统中身份以承诺形式存在、事故/违规经授权追溯必然可达个人——飞证让**合规飞行的隐私成本更低**，而不是让黑飞更容易。定位是"隐私保护且更合规"。

## 3. 系统总览

### 3.1 参与方与信任关系

| 参与方 | 形态 | 职责 | 知道什么 |
|---|---|---|---|
| **飞手** | 唯一人类角色 | 注册、申请、飞行 | 自己的一切 |
| 登记权威（RA） | 自动化签发服务（演示中=自建 CA 仪式；生产语境=民航登记/执照机构） | 签发实名承诺凭证、子凭证、令状协作解锁 | 实名身份（密文保管），**不知道**某次匿名申请是谁 |
| 授权服务（政策引擎） | 自动化服务，无人工审批员 | 验 ZK 证明→签令牌→链上注册 | **只有**合规结论+公开参数，零身份 |
| 审计方 | 单一审计席位（单屏治理面） | 令状→解锁→留痕 | 解锁前与公众无异，解锁需 RA 协作（双控） |
| 无人机 | 设备（演示=SITL 软件在环） | 验令牌、固件围栏、遥测签名 | 令牌内容，不知道主人是谁 |

关键信任结构：**审计方单独不能追踪**——解锁实名必须凭令状且由 RA 协作解密，解锁行为本身上链留痕（"审计审计者"）。

### 3.3 一次飞行的完整旅程（主循环）

```
①注册：实名→盐化承诺 C=SM3(盐‖身份证‖资质‖序列号哈希)→RA 签名凭证→链上登记承诺哈希
②申请子凭证：每次飞行前领一份"一次性"子凭证（新身份标量/新盐/新钥）→跨次申请不可关联
③匿名申请：提交 AUTH 零知识证明（不含任何身份字段，通道无账号）——证明生成约几十秒，异步等待
④自动授权：验证证明→查政策表→签令牌→链上登记+烧毁一次性 nonce
⑤验签解锁：地面站验令牌→把高度上限写进固件围栏→无人机才可启动
⑥飞行留痕：遥测 1Hz 采样→SM3 哈希链→每 60 秒链头签名上链锚定（轨迹本体永不上链）
⑦超限取证：固件围栏硬拦截+事件自动上链
⑧落地合规：可选生成 TRAIL 证明——"全程未超限"，轨迹零披露
⑨事故追溯：审计令状上链→RA 协作解密→定位到人→全程留痕可查
```

## 4. 零知识证明一分钟（队友 primer）

零知识证明（ZK）让证明者说服验证者"某个结论为真"，却**不泄露结论以外的任何信息**。例如："我持有机构签发的有效凭证"可以是真的且可验证，但验证方学不到凭证里写了什么。

本系统用的是**透明 SNARK**（HyperPlonk+Basefold，钉定自团队论文的电路栈）："透明"=不需要可信设置仪式（没有"被泄密的毒物参数"问题，这是答辩加分点）；电路建在 **SM2 椭圆曲线的域上**、哈希全用 SM3——这使验证 SM2 签名、计算 SM3 承诺在电路里是"原生"操作，比把国密算法硬塞进国际算法 SNARK（需 10~50 倍代价的非原生模拟）有代差优势。

两个关键词：
- **公开输入**：验证方看得到的参数（政策版本、高度上限、一次性 nonce…）。
- **私密见证**：只有证明者知道的数据（身份证号、盐、私钥…），进电路但不出电路。

## 5. 功能设计详解（做什么 · 怎么做 · 为什么这么设计）

### 5.1 注册与实名承诺凭证

**做什么**：飞手注册账号，提交实名信息与操作资质，RA 生成凭证。
**怎么做**：RA 生成 16 字节随机盐，计算承诺 `C = SM3(盐 ‖ 身份证号(18B) ‖ 资质等级(1B) ‖ 序列号哈希(16B))`，用 RA 私钥对含 C 的结构化报文 M_A（165B）做 SM2 签名。凭证=该签名；链上只登记 `SM3 凭证哈希` 与状态；身份证号等原像用用户的公钥做 ECIES 加密后由用户自己保管。
**为什么**：①实名是法定义务，必须可追溯；②但身份不需要躺在平台明文库——承诺让"同一份身份"可验证而不可读；③**加盐**是生死线：身份证号是低熵数据（地区码+生日+顺序码，空间约 10^10 且有校验位），无盐哈希等于把号挂出来供离线穷举，加盐后承诺不可枚举；④序列号进承诺=凭证与"这一台"无人机绑定，防一证多机。

### 5.2 一次性子凭证（跨次不可链接）

**做什么**：让"同一飞手的第 1 次申请"和"第 100 次申请"在密码学上**无法被关联**。
**怎么做**：每次申请前，飞手经认证通道向 RA 领一份短效（默认 24h）子凭证——全新的身份标量 id′、新盐、新密钥对（私钥在本机生成，RA 只见公钥），RA 对新报文签新名。申请里出现的是子凭证，且每份只用一次。
**为什么**：SM2 签名**不可重随机化**（数学性质：给定签名无法改造出同钥新签名），所以"同凭证重复出示必然同签名、必然可关联"——新鲜度的唯一密码学来源就是**让签发方每次重新签**。这就是子凭证机制的本质。诚实边界两条：①RA 若刻意记录"何时发了子凭证"，可通过时间近似关联（缓解=批量预签+延迟使用，说明书如实声明）；②对平台自身完全隐藏需盲签名，明确不做——因为"RA 协作可追溯"正是监管所需的**设计特性**而非缺陷。

### 5.3 起飞申请与 AUTH 资格证明

**做什么**：飞手提交起飞申请——不交身份证、不交属性表，交一份 ZK 证明。
**怎么做**：地面站从本地加密存储解出凭证原像，组装见证，生成 AUTH 证明（异步任务，进度可见，预估几十秒级[推得]），然后经**匿名通道**（无账号、会话零身份列）提交给授权服务。
**证明的语句**（唯一、融合，不再分档）：

> "我持有 RA 对承诺 C 签发的**有效子凭证**；C 的原像里：资质等级 ≥ 该机型类要求（范围门）；无人机序列号哈希 = 本次申请的序列号哈希（等值钉）；凭证未过期（有效期谓词）；本次申请绑定此飞行计划哈希、此 nonce、此政策版本（用途绑定）。"

**公开输入**：政策版本、机型类、该类高度上限、所需资质等级、序列号哈希、计划哈希、nonce、时间锚、RA 公钥引用、电路指纹。
**私密见证**：盐、身份证号、资质等级、序列号、子凭证私钥/身份标量、过期时间、RA 签名。
**为什么这么切**：①机型类公开——Remote ID 本就广播它，不构成新增泄露，且高度上限按类查公开政策表，政策改版零电路改动；②飞行计划**本体不出设备**，只有哈希进证明做绑定——位置意图对授权服务也不可见（管制空域的完整计划审批依法本就要监管方看计划，明确划出范围外，见 §11）；③四档融合为一条语句——上一代系统四档是历史沉积，本系统从第一天只需一条资格语句。

### 5.4 自动授权与签名令牌

**做什么**：验证证明、签发令牌、上链登记。全程无人工。
**怎么做**：授权服务按序执行——比对链上电路指纹（不符拒绝启动，fail-closed）→ 检查 nonce 未用 → 秒级验证 ZK 证明 → 按机型类查政策表得高度上限 → 用政策域密钥签令牌 → 链上登记授权记录并**烧毁 nonce**。令牌内容：授权 ID、序列号哈希、高度上限、时间窗、nonce、政策版本、SM2 签名（几百字节）。
**为什么**：①"政策公开编码进电路+合约、无审批员"——没有人看你的申请，只有密码学在审，这条叙事干净且免掉一整个角色体系；②**令牌而非"验证码"**——手工验证码可重放、无绑定、无新鲜性，是玩具机制；签名令牌绑定设备+时间+参数+一次性 nonce，是工程可信形态（工业先例：DJI Geo 的解禁就是签名授权机制）；③nonce 链上烧毁=授权单一性有**链级保证**，不依赖任何单一服务器不说谎。

### 5.5 启动闸门：两层设计

**做什么**：没有有效令牌，无人机物理上飞不起来。
**怎么做**：
- **地面站层（协议层）**：本地桥接服务验令牌 SM2 签名+序列号绑定+时间窗，任一失败拒绝发送启动指令并留审计行；
- **固件层（强制层）**：把令牌中的高度上限写入飞控围栏参数（ArduPilot 的 FENCE_ALT_MAX），飞行中越限由**固件在硬实时环里拦截**（自动悬停/返航）——不是地面站"劝阻"，是飞控拒绝。
**为什么分层+诚实声明**：地面站是用户自己的软件，理论上可被绕过（TCB 边界，如实声明）；固件围栏不可绕。真机部署路径=伴飞计算机+国产安全芯片（SE/TCM，SM2 验签毫秒级是这类芯片的标准能力）写入落地路线。**分层声明本身就是加分项**——评委问"用户改自己的地面站怎么办"，答案在威胁模型里等着。

### 5.6 飞行留痕：遥测哈希链+检查点锚定

**做什么**：飞行记录可证明未被篡改，但轨迹本体不上链。
**怎么做**：地面站按 1Hz 采样高度等遥测，逐条接入 SM3 哈希链；每 60 秒对链头签名并经授权服务上链锚定（FISCO BCOS 遥测锚定合约）。第三方可离线验真：重算哈希链→对链上锚点→一致 exit 0 / 被篡改 exit 2。
**为什么**：链上只有链头哈希——"这份记录存在且没被改过"可证，"记录内容是什么"不公开；轨迹明细留在用户本地，令状解锁才可调取。这是"存证不暴露"的标准密码学形态（哈希链+锚定），成本极低而证明力极强。

### 5.7 超限自动取证

**做什么**：超过申请高度，系统自动留下不可否认的违规记录。
**怎么做**：固件围栏触发（硬拦截）产生事件；地面站同时监测遥测，超限即生成事件哈希上链（事件类型：固栏触发/监测超限/通信中断/迫降）。
**为什么**：违规记录与飞行哈希链、授权记录同链关联（授权 ID 贯穿），事后无法抵赖也无法单独删除——链的"状态变更权威"语义。

### 5.8 落地合规证明（TRAIL，电路原创锚）

**做什么**：落地后可生成第二份 ZK 证明："全程最大高度 ≤ 授权上限"——**轨迹明细零披露**。
**怎么做**：电路内从遥测样本重算 SM3 哈希链、对齐飞行中锚定的公开链头（防换记录），逐点证明 h_i ≤ 上限，时间戳证明严格连续（1Hz 无空隙，防稀疏采样藏超限），并验证 K 个检查点签名。参数：样本上限 1024（约 17 分钟），更长飞行分段证明。
**为什么**：①"轨迹即隐私"是无人机域最敏感的点——TRAIL 让连审计方都只能得到"合规/不合规"结论；②采样完整性诚实分工：实时强制的权威=固件围栏；TRAIL 证明对象=**已锚定的记录**（防篡改）+**无空隙**（防藏 excursion）——两者合起来覆盖"固件失效"残余场景；③这是本系统电路工作相对已验证栈的**新增语句类别**（对承诺序列的链验证+逐点范围），是作品电路原创性的锚。

### 5.9 令状追溯

**做什么**：事故/违规后，把匿名记录合法地还原到个人。
**怎么做**：审计方创建令状（案号+目标记录+法律依据哈希）→ 上链留痕 → RA 验令状后解密实名映射 → 返回关联结果 → 解锁记录上链。无令状请求=拒绝（负例有测试）。
**为什么**：①追溯可达个人=对监管的承诺；②令状先行+双控（审计方+RA）+解锁留痕=追溯权本身被治理——"审计审计者"；③对比"平台直接查库"，这里的每一次去匿名化都是显式的、有据的、可复查的。

### 5.10 审计台

单屏治理面：创建令状→查看解锁结果→浏览令状日志/检查点/违规事件。审计员以密钥认证（无口令体系——没有多角色治理体系，YAGNI 裁剪）。它不是第三个"用户角色"，是系统的治理边界，刻意最小化。

## 6. ZK 电路使用专章

### 6.1 两条语句总表

| | AUTH 资格证明 | TRAIL 轨迹合规证明 |
|---|---|---|
| 时机 | 起飞前，主循环内 | 落地后，离线 |
| 证明什么 | 持有效实名子凭证+资质达标+序列号绑定+未过期+绑定本次申请 | 全程高度未超限（对已锚定记录） |
| 隐藏什么 | 身份证号、资质值、序列号、盐、子凭证身份 | 轨迹明细（高度序列） |
| 约束构成 | SM3 承诺原像+SM2 验签+范围门+等值钉+有效期谓词+绑定方程 | SM3 链展开验证+逐点范围门+时间连续门+K 点验签 |
| 规模预估 [推得] | ~10 万约束级，prove 秒十级 | 15~40 万约束级（n=1024,K=10），prove 几十~百秒 |
| 实时性 | 不在实时路径（申请异步）；启动验令牌=毫秒级签名校验 | 离线，无实时要求 |

### 6.2 电路栈与 gadget 构成

底层=团队论文成果的钉定复用（诚实口径）：HyperPlonk+Basefold，SM2 域原生，零可信设置。语句由以下 gadget 拼装——前四项为已验证资产直接复用，后两项为本系统电路工作：

1. **SM3 查表化**：布尔电路整块 SM3 约 6 万约束 → 查表化 4 约束+8 查表（58.9×），有引理与覆盖声明背书——AUTH 的承诺原像、TRAIL 的链展开都靠它才可行；
2. **SM2 验签**：电路内重建报文→验签，配 EC 窗口化压缩椭圆曲线部分成本（B3 批随带完成）；
3. **范围门**：资质等级 ≥ 要求（AUTH）、逐点高度 ≤ 上限（TRAIL）；
4. **等值钉/有效期谓词/绑定方程**：序列号、过期时间、计划哈希+nonce+政策版本；
5. **TRAIL 链展开验证 gadget**（新研发，B6 批）：电路内重算 n 步 SM3 链并对齐公开链头；
6. **变异测试体系**：电路格级变异全覆盖扫描（逃逸 0 的方法论继承），负例必须被数学拒绝而非输入校验。

### 6.3 哪里刻意不用 ZK（反设计，同等重要）

令牌验证（毫秒级签名校验）；遥测锚定（哈希链）；追溯（承诺打开+令状）；政策查询（公开数据）。ZK 只站在"最小披露才能解决"的刀刃上——这是对"功能繁杂、为炫技而密码学"的直接反设计，也是答辩时"为什么这里不用 ZK"的预备答案。

## 7. 联盟链设计

### 7.1 链的三条存在理由（每个链上功能必须归入其一）

①授权记录不由单一运营方掌控（运营方可篡改可抵赖）；②遥测留痕多方锚定防单方篡改；③追溯行为本身可审计。归不进三条的链功能一律砍掉。

### 7.2 四合约（FISCO BCOS 2.9 国密四节点，全链路国密）

| 合约 | 职责 | 关键接口 |
|---|---|---|
| IdentityRegistry | 凭证承诺哈希+状态；**令状日志** | registerCommitment / setStatus / logWarrant / isRevoked |
| PolicyRegistry | 政策参数版本化公示；**电路身份指纹** | publishPolicy / pinCircuit / setClassRule / getClassRule |
| FlightAuthRegistry | 授权登记+**nonce 烧毁**；authId 全系统贯穿键 | recordAuth / burnNonce / revokeAuth / nonceUsed |
| TelemetryAnchor | 检查点锚定；违规事件自动取证 | anchorCheckpoint / recordEvent / verifyHead |

### 7.3 链上不做什么

验证 ZK 证明（链下验证服务做，链只锚结论——这才是"合约与 ZK 融合"的工程诚实形态）；存轨迹明文（只有链头哈希）；做用户侧共识节点（"用户注册链上节点"已修正为**用户公钥/DID 上链锚定**——共识节点是全量服务端进程，不可能寄生于用户终端，这是初稿概念错误的纠正记录）。

## 8. 密码算法清单（国密口径）

| 算法 | 用途 |
|---|---|
| SM2 | 凭证/令牌/检查点签名与验签、子凭证密钥对、ECIES（身份原像加密、令状协作） |
| SM3 | 盐化承诺、哈希链、凭证据哈希、政策/电路指纹、电路内全部哈希（查表化） |
| SM4-GCM | 本地密钥库加密、实名映射密文落库 |
| PBKDF2-HMAC-SM3 | 用户本地密钥库口令派生 |
| SM2 域透明 SNARK | AUTH/TRAIL 两语句的零知识证明（零可信设置） |

明确不做后量子（SM2 是椭圆曲线，Shor 可破）——本作品不碰 PQ 叙事，避免与电路核心互斥。

## 9. 与市面相似系统对比

### 9.1 现有系统逐个看

- **民航局 UOM 平台**（无人驾驶航空器一体化综合监管服务平台）：实名登记+飞行申请的法定入口。集中式；身份、计划全量明文交平台；轨迹无密码学锚定。**它履行监管职能，我们不取代**（见 9.4）。
- **DJI Geo / 厂商围栏解禁**：按需解禁飞限区，机制=厂商签发的授权——**签名令牌的工业先例**，但签发黑盒、数据入厂商云、与实名合规体系脱节。
- **Remote ID / AeroScope**：广播 ID+位置，任何人可收——隐私张力的直接来源（痛点 1）。
- **厂商飞行记录云同步**：轨迹明细入厂商服务器，用户无密码学控制。
- **学术界 privacy-preserving / blockchain UTM**：2019 年起有论文提出隐私 UTM、链上 UTM 的构想，但**无可运行的完整系统**，更无国密 ZK 电路栈。

### 9.2 对比表

| 维度 | UOM | DJI Geo | Remote ID | 学术提案 | **飞证** |
|---|---|---|---|---|---|
| 授权形态 | 平台人工/流程审批 | 厂商签名解禁 | 无（纯广播） | — | **ZK 证明→自动签令牌** |
| 身份数据流 | 平台全量明文 | 厂商云 | **广播给所有人** | 提案级 | **承诺化，零披露，令状才可达** |
| 轨迹数据流 | 平台留存 | 厂商云 | 广播位置 | 提案级 | **本地哈希链，链上只有链头** |
| 跨次关联防护 | 无（天然关联） | 无 | 天然关联 | 提案级 | **一次性子凭证，密码学不可关联** |
| 追溯机制 | 平台查库 | 厂商配合 | 广播身份即追溯 | 提案级 | **令状+RA 双控+解锁留痕** |
| 篡改防护 | 平台自证 | 厂商自证 | 无 | — | **哈希链+链锚+第三方离线验真** |
| 密码学强度 | 登录口令级 | 厂商签名 | 明文广播 | 论文级 | **全链国密+透明 SNARK** |
| 物理强制 | 无 | 围栏（黑盒） | 无 | — | **令牌→固件围栏（分层 TCB 声明）** |
| 可运行性 | 已运行 | 已运行 | 已运行 | 无系统 | **SITL 全链路可运行演示** |

### 9.3 为什么以前没人做成（答辩标准答案）

不是没人想到（学术提案存在），是三个条件此前不同时具备：①ZK 证明系统直到 lookup argument 与透明证明系统成熟后才工程可行（否则电路体积/证明体积不可用）；②行业激励错位——平台要数据聚合，监管要能见度，没人有动力做"最小披露"；③国密 ZK 电路栈此前不存在。第三个条件正是我们手里已有的东西——**这个技术窗口是本作品存在的前提**。

### 9.4 我们不取代什么（诚实，防评委反问）

不取代 UOM 的监管职能（管制空域计划审批依法需要监管方见计划——范围外）；不取代 Remote ID 的广播合规（那是法定义务）；不取代固件围栏（我们消费它、把授权参数写进去）。飞证是这些体系之上的**密码学合规层**：让"可追溯"不必再以"人人可见"为代价。

## 10. 亮点特点清单（答辩弹药，每项三段式）

1. **密码学合规点火**——ZK 验证结论直达物理硬件（固件围栏），密码学第一次"扣押"物理行为。强在：纯数字系统没有的维度；证明：现场演示无效令牌拒绝启动。
2. **国密 ZK 电路栈代差**——SM2 域原生+SM3 查表化+零可信设置。强在：国际 SNARK 塞国密需 10~50 倍代价；证明：查表化 58.9× 有引理背书，"为什么不用现成 SNARK"有实测答案。
3. **身份最小披露闭环**——实名承诺化→子凭证不可链接→令状双控解锁→解锁留痕。强在：每一步密码机制对应一条法规张力；证明：链上/授权服务零身份列可现场 grep，令状外解锁被拒。
4. **轨迹零上链的存证**——哈希链+链头锚定+第三方离线验真。强在："存在且未篡改"可证而内容不公开；证明：验真脚本 exit 0/2 现场跑。
5. **TRAIL 语句（电路原创锚）**——对已锚定遥测序列的链内验证+逐点范围+无空隙时间。强在：已验证栈上**新增的语句类别**，直击"轨迹即隐私"；证明：超限样本/时间空隙负例被数学拒绝。
6. **链级防重放**——nonce 上链烧毁，授权单一性不依赖任何单一服务器诚实。强在：把"防重放"从应用层约定升为链级事实；证明：重放请求负例。
7. **负例一等公民+对抗性演示**——过期令牌/篡改参数/换序列号/无令状解锁全部有演示位，评委可亲手攻击。强在：安全叙事可证伪，不演成功流自嗨；证明：S3 场景脚本。
8. **TCB 诚实分层**——地面站层（可绕，声明）/固件层（不可绕）分工明示，真机路径（SE 芯片）成文。强在："宣称=实现"的成熟度信号；证明：威胁模型文档与演示一一对应。

## 11. 诚实边界与范围外（全部成文，不藏）

- **固件/地面站 TCB**：地面站可被用户绕过（声明）；固件围栏不可绕；时钟为信任边界。
- **RA 时序侧信道**：子凭证签发与匿名申请的时间近似可关联——声明+批量预签缓解。
- **平台账户库**：登录账户体系知道"这个人存在"；不知道"哪次飞行是他"（匿名申请通道），实名映射密文落库+令状才可解。
- **TRAIL 采样前提**：证明对象是已锚定记录，与固件围栏构成双保险而非互替。
- **范围外**：管制空域完整计划审批；真机部署（有 SE 芯片落地路线）；对平台自身的盲签隐藏；多方门限追溯；后量子；链上验证 SNARK；空域多边形电路内判定。

## 12. 演示形态（SITL，无真机）

用 ArduPilot SITL（与真机相同固件跑在电脑上）+ 自研轻量地面站（pymavlink 桥接），投影演示四场景：
- **S1 合规全流程**：注册→子凭证→匿名申请（证明进度条）→令牌→SITL 解锁起飞→检查点锚定→落地 TRAIL；
- **S2 超限取证**：脚本爬升越限→固件拦截→违规自动上链→审计台可见；
- **S3 负例三连（评委可上手）**：过期令牌拒绝启动 / 篡改 alt_max 验签失败 / 他人序列号绑定失败；
- **S4 令状追溯**：从事故事件还原到个人，令状留痕全程可见。

专家说服力论证链：SITL=真实飞控代码（仿物理不仿安全逻辑）+UTM 研究的标准实验形态+DJI Geo 令牌机制的工业先例+TCB 分层诚实声明。
