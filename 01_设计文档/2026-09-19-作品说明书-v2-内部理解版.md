## 1. 这是什么系统

飞证是一套面向**低空经济场景**的无人机合规飞行系统：飞手提交起飞申请时，用**零知识证明**证明"我有实名登记凭证、我有相应操作资质、我的无人机已绑定、我的凭证未被吊销、申请高度不超该机型法规上限"——而**不提交身份证号和任何属性明细**。系统自动核验通过后签发**签名授权令牌**，无人机只有拿到有效令牌才能解锁启动，高度被固件围栏硬性限制；全程飞行留痕锚定上链，发生事故或超限时**凭审计令状可追溯到具体个人**——除此之外，任何人（包括平台运营方自己）都看不到"谁在飞、在哪飞、飞了多高"。

参赛定位：全国密码技术竞赛软件系统作品，密码三支柱=**国密算法（SM2/SM3/SM4）+ 零知识证明 + 联盟链**。

**法律定性（重要，全队统一口径）**：本系统令牌是**治理层门禁与合规基础设施凭证，不是行政许可**。主场景是法规无需逐次审批的适飞空域；价值主张是自愿采用的合规与隐私能力（厂商预装/机队管理/保险激励），远期与 UOM 对接。禁用"替代审批/行政许可"表述。

## 2. 要解决的三个真实痛点

1. **Remote ID 广播与隐私的法定张力。** GB 42590-2023 强制无人机广播 ID+位置，广播信号**任何人都能接收**——追踪者可借此定位"谁在拍什么"。飞证的回答：合规所需的"可追溯性"不必建立在"人人可见"上。
2. **轨迹敏感性。** 航拍轨迹=家庭位置+拍摄对象+生活规律。现有平台把全体飞手数据聚合成中心数据库，一次拖库就是全员移动画像泄露。
3. **最小必要原则的反面现状。** 现行模式每次申请都向平台交明文身份+计划；核验"是否合规"只需要一个**结论**，不需要数据本体。

**叙事红线（全体统一）**：隐私保护对象是"平台运营方与公众的过度收集"，**不是对抗监管**。实名制是法定义务，系统中身份以承诺形式存在、事故/违规经授权追溯必然可达个人——飞证让**合规飞行的隐私成本更低**，而不是让黑飞更容易。定位"隐私保护且更合规"。

## 3. 系统总览

### 3.1 参与方与信任关系

| 参与方 | 形态 | 职责 | 知道什么 |
|---|---|---|---|
| **飞手** | 唯一人类角色 | 注册、申请、飞行 | 自己的一切 |
| 登记权威（RA） | 自动化签发服务（演示=自建 CA 仪式；生产语境=民航登记/执照机构） | 签发凭证/子凭证、维护撤销累加器树并公示纪元根、令状协作解锁（实名映射双通道：ECIES 用户自持+RA 域钥密文库存——令状批准后 RA 解密，流程双控） | 实名身份（密文保管），不知某次匿名申请是谁 |
| 授权服务（政策引擎） | 自动化服务，无人工审批员 | 受理门控→验 ZK→签令牌→链上注册 | 合规结论+公开参数，零身份 |

| 无人机 | 设备（演示=SITL，桥接**模拟设备钥**） | 验令牌、固件围栏、遥测设备钥签名 | 令牌内容，不知主人是谁 |

```

⑦飞行留痕：2Hz 遥测→SM3 哈希链（设备钥签名）→每 60s 检查点锚定（轨迹本体永不上链）
⑧超限取证：固件围栏硬拦截+事件自动上链（固件事件时间戳为权威）
⑨落地合规：可选生成 TRAIL 证明——"设备签名且已锚定的记录显示全程未超限"，轨迹零披露
⑩事故追溯：审计令状上链→RA 协作解密→定位到人→全程留痕可查
（吊销：RA 更新撤销累加器→新纪元根上链→被吊销者下一次申请即被电路数学拒绝——即时生效）
```

## 4. 零知识证明一分钟（队友 primer）

零知识证明（ZK）让证明者说服验证者"某个结论为真"，却**不泄露结论以外的任何信息**。本系统用**透明 SNARK**（HyperPlonk+Basefold，钉定自**本团队自有论文**的电路栈）："透明"=零可信设置（没有"被泄密的毒物参数"）；电路建在 **SM2 椭圆曲线域上**、哈希全用 SM3——验证 SM2 签名、计算 SM3 承诺在电路里是"原生"操作，比把国密算法塞进国际曲线 SNARK（需 10~50 倍代价的非原生模拟）有代差优势。

两个关键词：**公开输入**（验证方可见：政策版本、高度上限、撤销纪元根、nonce…）；**私密见证**（只有证明者知道：身份证号、盐、私钥、撤销路径…），进电路但不出电路。

## 5. 功能设计详解（做什么 · 怎么做 · 为什么）

### 5.1 注册与实名承诺凭证

**做什么**：飞手注册，提交实名信息与资质，RA 签发凭证。
**怎么做**：RA 生成 16B 随机盐，`C = SM3(盐 ‖ 身份证号18B ‖ 资质等级1B ‖ 序列号哈希16B)`（51B，SM3 单块），对含 C 的 165B 报文 M_A 做 SM2 签名。链上只登记主凭证哈希与状态；原像用用户公钥 ECIES 加密由用户自持。
**为什么**：①实名是法定义务必须可追溯；②身份不需要躺平台明文库——承诺可验证不可读；③**加盐是生死线**：身份证号低熵（空间 ~10^10 有校验位），无盐哈希=挂出来供离线穷举；④序列号进承诺=凭证与"这一台"绑定，防一证多机。

### 5.2 一次性子凭证（跨次不可链接）

**做什么**：让同一飞手的任意两次申请在密码学上**无法被关联**——包括在链上。
**怎么做**：每次申请前领一份短效（≤24h）子凭证：全新身份标量/新盐/新密钥对（私钥本机生成，RA 只见公钥），RA 签新名。链上授权记录存**子凭证哈希**（每申请全新）——同一飞手的飞行记录在链上逐次互不关联。
**为什么**：SM2 签名**不可重随机化**（数学性质），同凭证重复出示必然同签名可关联——新鲜度唯一来源就是签发方每次重签。诚实边界：①RA 可通过签发/取见证时序做近似关联（缓解=配额+批量预签+公开镜像，已声明边界）；②对平台自身完全隐藏需盲签——明确不做，"RA 协作可追溯"是监管所需的**设计特性**。

### 5.3 起飞申请与 AUTH 资格证明

**做什么**：不交身份证、不交属性表，交一份 ZK 证明+一次性子凭证签名。
**怎么做**：地面站解出凭证原像组装见证，生成 AUTH 证明（异步，几十秒级[推得]，进度可见），经**匿名通道**提交：ZK 证明+公开实例+**子凭证签名（公开提交）+一次性会话公钥**。
**证明的语句**（唯一、融合）：

> "我持有 RA 签发的有效子凭证；原像满足：资质等级 ≥ 该机型类要求（范围门）；序列号哈希=申请序列号哈希（等值钉）；凭证未过期（有效期谓词）；**主凭证不在当前纪元撤销累加器中（SMT 非成员证明）**；本次申请绑定此计划哈希+nonce+政策版本（用途绑定）。"

**公开输入**：政策版本、机型类、高度上限、所需资质、计划哈希、nonce、时间锚、**子凭证签名**、**撤销纪元根**、RA 公钥引用、电路指纹。**序列号不出现在任何公开面**（sn_h 已收进承诺 C 原像——设备级跨次关联点消除，B3 实现定谳）。
**私密见证**：盐、身份证号、资质等级、序列号、子凭证私钥/身份标量、过期时间、**SMT 认证路径**。
**为什么这么切**：①机型类公开（Remote ID 本就广播），上限按类查公开政策表，政策改版零电路改动；②飞行计划**本体不出设备**只有哈希入证明（管制空域完整计划审批依法要监管方见计划，明确范围外）；③**子凭证签名公开提交不破坏申请匿名**——它是一次性数据，关联需要同一签名出现两次，而它只出现一次；公开它换来受理层毫秒级验签门控（见 5.4 防滥用）；④四档融合为一条语句——上一代四档是历史沉积，本系统第一天只需一条。

**匿名性的精确边界（诚实口径）**：子凭证哈希在 RA 签发记录与受理记录中同形存在——若 RA 与授权服务同属一个运营方且共享存储，一条哈希等值 JOIN 即可还原每次飞行的身份，令状双控被绕过。故生产部署的架构前提=**RA（登记权威）与授权服务分属法定两主体**，且 RA 签发面不落可 JOIN 键（配额只计数不存哈希）。演示单体部署不含此组织分离——组织级 TCB 声明，非密码学强制（盲签明确不做，框架 §十三）。

### 5.4 自动授权与签名令牌

**做什么**：验证证明、签发令牌、上链登记、加密返回。全程无人工。
**怎么做**：
- **受理门控（廉价先于昂贵）**：会话钥格式→子凭证签名验签（毫秒）→nonce 链上查重→电路指纹比对→通过才进 ZK 验证队列。电路内仍全量验证——宿主检查是防滥用门控，电路是密码学权威，两层角色分离。
- **签发**：查政策表→签令牌（**令牌含 plan_hash——证明绑定的计划与授权不可脱节**，v2.2）→链上登记（**含证明摘要 proof_digest**）→烧毁 nonce→令牌+回执以**会话公钥加密**返回；**128 位回执码**支持异步/跨设备查询；回执与会话表零身份列。
- **可审计签发**：判决件三件套按 authId 归档可下载，任何第三方可用公开验证工具对链上摘要**事后复验**——运营方若跳过验证直接签发，作弊必然可检出、证据不可篡改。
**为什么**：①无审批员=没人看你的申请；②令牌而非验证码（DJI Geo 解禁即签名令牌的工业先例）；③nonce 链上烧毁=授权单一性有链级保证；④**"先验证后签发"由可审计信任背书**——信任无法消除，但可以让背叛必然留证；⑤匿名出口与入口同级匿名（会话钥加密+回执码），否则前端匿名回程实名，最小披露在最后一米破功。

### 5.5 启动闸门：两层设计

**做什么**：没有有效令牌，无人机物理上飞不起来。
**怎么做**：地面站层验令牌（签名/序列号/时间窗），失败拒绝发 ARM 指令并留审计行；固件层把高度上限写入飞控围栏参数，越限由**固件硬实时拦截**（自动悬停/返航）。
**为什么分层+诚实声明**：地面站是用户自己的软件，理论可绕（TCB 声明）；固件围栏在指定飞控、参数面锁定与可信固件前提下构成硬拦截（S2 实测 32.39m 触发 [实测]）；「不可绕」的前提=参数面锁定+厂商签名固件（生产前提，TCB 边界显式声明）。真机路径=伴飞计算机+国产安全芯片（SE/TCM）。分层声明本身就是加分项——"用户改自己的地面站怎么办"的答案在威胁模型里等着。

### 5.6 飞行留痕：设备钥签名的遥测哈希链+检查点锚定

**做什么**：飞行记录可证明未被篡改、**出处为设备**，轨迹本体不上链。
**怎么做**：地面站 2Hz 采样遥测接入 SM3 哈希链，链头由**设备侧身份钥**签名（演示=桥接进程模拟设备钥并 TCB 声明；真机=SE/TCM 芯片）；每 60 秒检查点（链头+围栏状态绑定）经授权服务上链锚定。第三方可离线验真（重算→对链→exit 0/2）。
**为什么签名方是设备钥而不是地面站**：地面站是用户软件——若由它签名，用户可从头伪造"全程合规"的假遥测链，哈希链只证明"事后没改"不证明"当初为真"；签名根移到设备身份，伪造代价提高到"伪造设备签名+同时伪造固件围栏状态"。**诚实边界**：记录缺失≠无罪（无遥测=无 TRAIL 证明资格，令状+设备扣押取证兜底）；安全时间=设备 TCB，违规事实时间戳以固件事件为权威。**可链接性分层（防误读）**：身份层跨次不可链接（recordAuth 零设备信息/D18）；**设备层可链接**——检查点锚定含设备签名，同设备的多次飞行在链上按设备钥可关联（无人机实名登记于 RA，设备即人）——这是防伪强度的来源而非缺陷；若应用要求设备层也不可链接，需设备钥每飞行轮换+匿名归属证明，属 R4 远期。

### 5.7 超限自动取证

**做什么**：超限自动留下不可否认的违规记录。
**怎么做**：固件围栏触发（硬拦截）+地面站监测双通道生成事件哈希上链（围栏触发/监测超限/通信中断/迫降）。
**为什么**：违规记录与飞行哈希链、授权记录同链关联（authId 贯穿），事后无法抵赖无法单独删除。**定位声明**：数字证据链是事故调查的**补充证据**，不替代物理取证。

### 5.8 落地合规证明（TRAIL，电路原创锚）

**做什么**：落地后可生成第二份 ZK 证明——"**设备签名且已锚定的记录显示全程高度 ≤ 授权上限**"，轨迹明细零披露。
**怎么做**：电路内重算 SM3 哈希链对齐公开链头（防换记录——链从公开 genesis 常量起步、逐块复制环强制），逐点证明 h_i ≤ 上限（2Hz 采样，n=128=64 秒段定档[实测]，更长分段），时间戳严格连续（防稀疏采样藏超限；时间字段=录制器 500ms 网格契约——墙钟抖动不进证明，真实性归录制器 TCB，与 D16 同层）；设备钥检查点签名在**锚定/装配面 fail-closed 验签**（报文/签名/公钥皆链上公开数据，任何第三方可离线复验——电路内重验公开数据零密码学收益，B6 定谳）。
**为什么**：①"轨迹即隐私"是本域最敏感点——连审计方都只得到"合规/不合规"结论；②采样完整性双保险：实时强制权威=固件围栏，TRAIL 证明对象=已锚定的设备签名记录+无空隙时间——覆盖"固件失效"残余场景；③语句语义诚实收窄（"记录显示合规"而非"客观合规"）与证据强度精确匹配；④这是相对自有论文栈的**新增语句类别**，电路原创锚。

### 5.9 令状追溯

**做什么**：事故/违规后把匿名记录合法还原到个人。
**怎么做**：审计方创建令状（案号+目标记录+法律依据哈希）→上链留痕→RA 验令状解密实名映射→返回结果→解锁记录上链。无令状请求=拒绝（负例有测试）。
**为什么**：追溯可达个人=对监管的承诺；令状先行+双控+解锁留痕=追溯权本身被治理（"审计审计者"）。

### 5.10 审计台

单屏治理面：创建令状→查看解锁→浏览令状日志/检查点/违规事件。审计员密钥认证（无口令体系）。不是第三个用户角色，是系统治理边界，刻意最小化。

### 5.11 撤销：即时生效的密码学机制

**做什么**：凭证/设备被吊销后，**下一次申请即被数学拒绝**——不是"等子凭证过期"。
**怎么做**：RA 维护以主凭证句柄为键的 SM3 稀疏 Merkle 树；吊销=更新叶+新纪元根上链公示；AUTH 电路内验证"我的句柄位置是非叶空槽"（非成员证明，全部 SM3 查表 gadget，约束增量约 1~2% [推得]）；公开面只见纪元根，不暴露撤销者以外信息。子凭证 24h TTL 保留为纵深防御。
**为什么**：撤销与匿名的张力是凭证系统经典难题——短效凭证（行业标准）解决"旧凭证存活期"但给不出即时性；撤销累加器进电路同时拿到**即时性+隐私性**（路径是私密见证），且完全复用现有 gadget 库。"无人机被吊销后还能飞多久"——答"一次都飞不了"，这是答辩硬通货。

## 7. 联盟链设计

### 7.1 链的三条存在理由

①授权记录不由单一运营方掌控；②遥测留痕多方锚定防单方抵赖；③追溯行为本身可审计。归不进三条的链功能一律砍掉。

### 7.2 四合约

| 合约 | 职责 | 关键接口 |
|---|---|---|
| IdentityRegistry | 主凭证哈希+状态；**撤销纪元根公示**；令状日志 | registerCommitment / setStatus / **setRevocationRoot** / logWarrant |
| PolicyRegistry | 政策参数版本化公示；电路身份指纹 | publishPolicy / pinCircuit / setClassRule |
| FlightAuthRegistry | 授权登记+nonce 烧毁+子凭证唯一性链级强制；**存子凭证哈希（逐次不可关联——v2.2 删 snHash：链上零设备信息）+证明摘要（可审计签发）** | recordAuth / burnNonce / revokeAuth |
| TelemetryAnchor | 检查点锚定（设备钥签名）；违规事件自动取证 | anchorCheckpoint / recordEvent / verifyHead |

### 7.3 链上不做什么

验证 ZK 证明（链下验证服务做+证明摘要上链供事后复验——链上直接验证存在四条死因：资源量级差 3~6 个数量级/EVM 字节码与 vp 体积硬限制/共识层架构负收益/验证器重实现风险反向）；存轨迹明文；当用户侧共识节点（用户=轻客户端签名交易）。

## 8. 密码算法清单（国密口径）

| 算法 | 用途 |
|---|---|
| SM2 | 凭证/子凭证/令牌/检查点（设备钥）签名验签、ECIES（身份原像/回执加密） |

## 10. 亮点特点清单（答辩弹药，每项三段式）

1. **密码学合规点火**——ZK 验证结论直达物理硬件（固件围栏）。强在：纯数字系统没有的维度；证明：现场无效令牌拒绝启动。
