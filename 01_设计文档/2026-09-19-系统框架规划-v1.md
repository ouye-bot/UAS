**Goal:** 构建一个以国密 ZK 证明为授权内核、联盟链为存证/治理底座的无人机合规飞行系统——合规证明解锁起飞，飞行留痕锚定上链，追溯直达个人，身份与轨迹全程零披露。

**Architecture:** 单一人类角色（飞手）；登记权威/政策引擎/审计台全部为自动化服务或治理面。ZK 出现在两个语句上（起飞资格证明 AUTH、轨迹合规证明 TRAIL），令牌验证与高度强制分别落在地面站协议层与飞控固件围栏层。FISCO BCOS 国密联盟链承载四合约（身份/政策/授权/遥测）。

**Tech Stack:** Python 3.11 FastAPI（后端服务）、Rust zkc + vendor 钉定电路栈（证明服务）、Solidity@FISCO BCOS 2.9 国密四节点（链）、Vue3 + pymavlink 桥接（地面站）、ArduPilot SITL（演示飞行器）、三语言国密库（SM2/SM3/SM4）。

## 一、一句话定位与叙事

> **合规证明解锁起飞，飞行留痕锚定上链，追溯直达个人，身份与轨迹全程零披露。**

痛点三实锚（答辩与说明书的根，禁泛化表述）：
1. **Remote ID 广播与隐私的法定张力**——GB 42590 强制广播 ID+位置，广播面任何人可收，追踪者可定位航拍者；本系统证明可追溯性不依赖广播级身份暴露。
2. **轨迹敏感性**——航拍轨迹=家庭位置+拍摄对象+生活规律；集中式平台聚合全体飞手轨迹是真实泄露面。
3. **平台画像风险**——逐次申请交明文身份+计划，平台数据库=全体飞手移动行为画像（《个人信息保护法》最小必要原则的反面）。

竞争差异化（答辩口径）：现有体系（UOM/厂商 Geo/Remote ID）把可追溯建立在"人人可见"上；学术隐私 UTM 有提案无可运行系统；国密 ZK 电路栈此前不存在——本作品三者同时成立，且合规结论**直达物理硬件**（固件围栏）。

## 二、总体架构与主循环

```
                    ┌────────────────────────────────────────────┐
                    │            FISCO BCOS 国密联盟链              │
                    │  IdentityRegistry │ PolicyRegistry          │
                    │  FlightAuthRegistry │ TelemetryAnchor        │
                    └───────↑──────────────↑─────────────↑────────┘
                            │锚定/状态      │政策公示      │检查点/令状
 ┌──────────┐  签发仪式  ┌──┴──────────────┴───┐   ┌────┴─────────┐
 │ 登记权威   │─────────→│   授权服务(政策引擎)   │←──│   审计台      │
 │ (自动CA)  │  子凭证   │ 验ZK证明→签令牌→注册   │   │ 令状→解锁→留痕 │
 └────┬─────┘          └──────────↑──────────┘   └──────────────┘
      │实名承诺凭证              │匿名申请(ZK证明,零身份)   ↑令状协作(RA解密)
      ↓                          │                        │
 ┌────────────────────────────┴────────────────────────┴───────────┐
 │                    飞手（唯一人类角色）                             │
 │  Web UI ──→ 本地地面站桥接服务：验令牌→设围栏→ARM / 遥测哈希链→锚定    │
 └────────────────────────────┬─────────────────────────────────────┘
                               │ MAVLink (UDP)
                        ┌──────┴───────┐
                        │ ArduPilot SITL│ 围栏=固件强制（FENCE_ALT_MAX）
                        └──────────────┘
```

**核心循环**：注册签发（加盐承诺凭证）→ 申请子凭证 → 匿名申请（AUTH 证明）→ 自动授权（验证明→签令牌→链上注册+nonce 烧毁）→ 验签解锁（地面站+固件围栏）→ 飞行留痕（遥测哈希链+检查点锚定）→ 超限自动取证（固件拦截事件上链）→ 落地合规证明（TRAIL）→ 令状追溯（RA 协作解锁，令状自留痕）。

**匿名性边界（写进说明书的诚实口径）**：授权服务与链上公开面零身份；**平台后端的账户库与 RA 的实名映射库是关联点**——实名映射密文落库、令状+RA 双控解密、解锁行为上链。不可链接（跨申请）经一次性子凭证达成；对平台自身隐藏需盲签，明确不做（登记权威协作追溯是设计特性）。

## 五、ZK 语句定义（本系统仅此两条）

### 5.1 AUTH——起飞资格证明（起飞前，主循环内）

**语义**：证明者持有登记权威对承诺 C 签发的有效子凭证，承诺原像满足：实名身份（隐藏）、操作资质等级 ≥ 该机型类要求、无人机序列号哈希=申请序列号哈希、凭证未过期，且本次申请绑定（计划哈希，nonce，政策版本）。

**报文 M_A（165B，沿用全语句重建形态——电路宿主重建逻辑高复用）**：

```
M_A = Z_A(32) ‖ x(id′_u·G)(32) ‖ C(32) ‖ pk′_u.x(32) ‖ pk′_u.y(32) ‖ exp_u BE(4) ‖ par(1)
C   = SM3( salt(16) ‖ id_number(18) ‖ cert_level(1) ‖ sn_h(16) )     # 51B，SM3 单块
sn_h = SM3( drone_serial )[0..16]
par = 0x02 | lsb(y(id′_u·G))
```

- 51B 原像 + 填充 ≤ 55B ⟹ **SM3 单块**，查表化 gadget 直接适用。
- `id′_u/pk′_u/salt′` 每次申请由 RA 子凭证仪式刷新（A3）⟹ 跨申请不可链接。

**公开实例（政策引擎可见）**：`policy_version(4B)、class_id(1B)、alt_max(u16)、required_level(1B)、sn_h(16B)、plan_hash(32B)、nonce(16B)、t_epoch(4B)、RA 公钥引用、电路 pin 指纹`。

**私密见证**：`salt、id_number、cert_level、sn、sk′_u、id′_u、r（出示随机化）、exp_u、RA 签名 (r_s,s_s)`。

**电路约束构成（全部现成 gadget）**：M_A 重建+SM3 三块（查表化）→ 词序折叠 e → SM2 验签（B3 完成 EC 窗口化）；C 原像绑定（单块查表 SM3）；`cert_level ≥ required_level` 范围门；`SM3(sn)==sn_h` 等值钉；`exp_u ≥ t_epoch` 有效期谓词；绑定方程（plan_hash/nonce/policy_version 实例钉）。

**机型类公开的口径**：机型类=公开输入（Remote ID 本就广播；高度上限按类查政策表，政策改版=新 policy_version，零电路改动）；序列号、身份、资质等级=隐藏。

**规模与性能预估 [推得，B3 实测定谳]**：结构与上一代承诺谓词档同族（gadget 复用+EC 窗口化增量），10 万约束量级；prove 秒十级（服务器窗实测定档位 caps）。

### 5.2 TRAIL——轨迹合规证明（落地后，离线）

**语义**：证明者知道一段遥测样本序列 (h_i, t_i)，其 SM3 哈希链头=飞行中已锚定的公开链头，每个样本高度 ≤ 授权上限，时间戳按声明采样率严格连续（无空隙），K 个检查点签名有效——结论"全程合规"成立，轨迹零披露。

**公开实例**：`chain_head(32B)、alt_max(u16)、t_start/t_end(4B×2)、sample_rate、K 个检查点公钥引用`。
**私密见证**：`n 组 (h_i,t_i)、K 个检查点签名`。

**电路约束构成**：SM3 哈希链展开验证（**新 gadget，B6 研发项**，查表化 SM3 使其可行）；n 个范围门 `h_i ≤ alt_max`；时间戳等值门 `t_{i+1}−t_i = 1/sample_rate`；K 个 SM2 验签（检查点签名，K≈10/10min@60s 间隔）。

**参数默认值**：采样率 1Hz；n 上限 1024（≈17 分钟），更长飞行**分段证明+分段极值核对**（本栈无递归/折叠，逐段展开是唯一路径——诚实边界）；检查点间隔 60s。

**采样完整性的防线分工（答辩必答）**：实时强制的权威=固件围栏（不可绕）；TRAIL 证明的对象=**已锚定的记录**（防记录篡改）+**无空隙时间连续**（防稀疏采样藏 excursion）。两者合起来覆盖"固件失效/未装围栏"的残余场景。

### 5.3 明确不用 ZK 的位置

令牌验证（地面站/飞控：签名校验，毫秒级）；遥测锚定（哈希链）；追溯（承诺打开+令状）；政策表查询（公开数据）。ZK 只站刀刃——这是对"功能繁杂"的直接反设计。

## 六、联盟链设计（FISCO BCOS 2.9 国密四节点，四合约）

**链的三条存在理由**（每个链上功能必须归入其一，归不进的砍掉）：①授权记录不由单一运营方掌控；②遥测留痕多方锚定防单方抵赖；③追溯行为本身可审计。

### 6.1 IdentityRegistry（身份注册表）
```solidity
function registerCommitment(bytes32 credHash, uint8 credKind) external onlyRA;
function setStatus(bytes32 credHash, uint8 status) external onlyRA;          // 1=有效 2=吊销 3=过期
function logWarrant(bytes32 warrantHash, bytes32 scopeHash) external onlyAuditor; // 令状自留痕
function isRevoked(bytes32 credHash) external view returns (bool);
```
- 链上只有承诺哈希与状态；**实名映射（credHash→uid→身份证密文）在 RA 库内密文落库**，令状+RA 双控解密（审计方单独不能追踪——治理性质）。

### 6.2 PolicyRegistry（政策注册表）
```solidity
function publishPolicy(string calldata version, bytes32 paramsHash) external onlyAdmin;
function pinCircuit(bytes32 pinFingerprint) external onlyAdmin;              // 电路身份指纹公示
function setClassRule(uint8 classId, uint16 altMaxM, uint8 requiredLevel) external onlyAdmin;
function getClassRule(uint8 classId) external view returns (uint16, uint8);
```
- 政策表种子=《无人驾驶航空器飞行管理暂行条例》公开数值（微型 50m/轻型 120m 等），实施时从条例原文逐条摘录并注明出处（禁手抄记忆）。
- `pinCircuit` 承接 A8：授权服务启动 fail-closed 比对链上指纹。

### 6.3 FlightAuthRegistry（授权注册表）
```solidity
function recordAuth(bytes32 tokenHash, bytes16 nonce, bytes16 snHash,
                    uint8 classId, uint16 altMaxM, uint40 tStart, uint40 tEnd,
                    bytes32 credHash) external onlyEngine returns (uint256 authId);
function burnNonce(bytes16 nonce) external onlyEngine;                        // 链级防重放
function revokeAuth(uint256 authId, uint8 reason) external onlyEngine;
function nonceUsed(bytes16 nonce) external view returns (bool);
```
- `authId` 是全系统贯穿键（遥测锚定/违规事件/令状 scope 都引用它）；链上无身份列，`credHash` 为假名。

### 6.4 TelemetryAnchor（遥测锚定）
```solidity
function anchorCheckpoint(uint256 authId, uint32 seq, bytes32 chainHead,
                          bytes calldata engineSig) external;               // 每60s
function recordEvent(uint256 authId, uint8 eventType, bytes32 eventHash) external; // 超限/事故自动取证
function verifyHead(uint256 authId, bytes32 chainHead) external view returns (bool);
```
- `eventType`：1=固件围栏触发 2=地面站监测超限 3=通信中断 4=迫降记录。
- 第三方离线验真：重算链哈希→重算检查点→链上回读（A9 模式，exit 0/2）。

**链不做的事**：验证 ZK 证明（链下验证服务做，链只锚结论）；存轨迹明文；充当用户侧共识节点（用户=轻客户端签名交易；"用户注册链上节点"的原始设想修正为**用户 DID/公钥上链锚定**）。

## 七、系统服务与模块设计

### 7.1 登记权威（RA，自动 CA）
- 注册仪式：用户实名提交（演示宇宙）→ 生成 salt（CSPRNG）→ 计算 C → RA 主钥签 M_A（**裸摘要通道+电路词序口径**，跨语言黄金向量钉定）→ `holder_secret_cipher=ECIES(pk_u, salt‖id‖cert‖sn)` 回用户 → credHash 上链。
- 子凭证仪式：用户经认证通道请求（RA 知 uid 但不知后续匿名申请的关联；**时序侧信道诚实声明**——缓解=批量预签/延迟使用）→ fresh id′/salt′/pk′（sk′ 端侧生成，服务端只收公钥）→ 签 M_A′ → 短效 exp′（默认 24h，≤ 主凭证）。
- 令状协作：验证令状（链上 WarrantLog 在案）→ 解密实名映射 → 返回解锁结果 → 解锁记录上链。

### 7.2 授权服务（政策引擎）
- 输入：AUTH 证明+公开实例（**匿名通道，无认证头**，会话零身份列）。
- 流程：pin 指纹比对（fail-closed）→ nonce 未用检查 → zkc verify（秒级）→ 机型类查政策表 → 签令牌 → recordAuth+burnNonce → 返回令牌。
- 令牌格式：`{authId, sn_hash, alt_max, t_start, t_end, nonce, policy_version, Sig_engine(前述全字段)}`。
- 政策钥域分隔派生自 KMS 主钥；政策改版=新 policy_version+PolicyRegistry 公示。

### 7.3 地面站（gcs/bridge + web）
- 验签 arm 闸门：收到令牌→SM2 验签+SN 绑定+时间窗检查→设 `FENCE_ENABLE=1/FENCE_ALT_MAX=alt_max`→ARM；任一失败拒绝并留本地审计行。
- 遥测记录器：1Hz 采样→SM3 哈希链→每 60s 链头签名→授权服务转锚定（授权服务代为上链，桥接不直连链）→围栏触发事件（STATUSTEXT/自动）捕获→recordEvent。
- TRAIL 任务：落地后组装见证→提交授权服务走证明队列→判决件归档+链上锚结论。
- Web UI 单角色四屏：申请（进度可见）/令牌与飞行/留痕与合规证明/我的记录。**负例按钮一等公民**（过期令牌/错 SN/超限，供演示与自检）。

### 7.4 审计台（单屏治理面）
- 三步：创建令状（案号+scope=authId/credHash+法律依据哈希）→ 上链 WarrantLog → RA 协作解锁 → 展示实名关联与全部留痕（令状日志、检查点、违规事件）。
- 认证=审计员密钥（无口令体系，YAGNI）；令状不可撤销只能追加更正记录。

## 八、SITL 集成设计

- **选型**：ArduPilot Copter SITL（WSL2 运行，`sim_vehicle.py`），pymavlink 桥接；围栏=`FENCE_ENABLE/FENCE_ALT_MAX` 固件参数；备选 PX4 SITL（若 ArduPilot 参数面在演示中受阻，B5 开工探针定谳，二选一后冻结）。
- **接口点五处**：①连接与状态流（GLOBAL_POSITION_INT 等，UDP 14550）；②令牌验证→围栏参数→ARM（闸门）；③遥测流→哈希链记录器；④围栏触发事件（STATUSTEXT+FENCE 状态）→自动取证；⑤航线注入（演示飞行剖面）。
- **TCB 分层声明**：地面站层闸门用户理论上可绕（协议层声明）；固件围栏不可绕（真机部署路径=伴飞计算机+国产 SE/TCM 芯片做令牌验签，写入落地路线）。
- **演示场景脚本（sim/，每场景一条判决行）**：
  - S1 合规全流程：注册→子凭证→匿名申请→令牌→SITL 解锁→飞行→检查点锚定→落地 TRAIL。
  - S2 超限取证：脚本爬升越限→固件拦截→recordEvent 上链→审计台可见。
  - S3 负例三连：过期令牌 arm 被拒 / 篡改 alt_max 令牌验签失败 / 他人 sn_hash 绑定失败。**现场对抗演示=评委可亲手改参数重放**。
  - S4 令状追溯：从事故事件回溯至个人，全程令状留痕可见。

## 九、威胁模型与 TCB 声明（摘要，B8 批展开成文）

| 对手 | 防线 |
|---|---|
| 授权服务运营方过度收集 | 匿名申请通道零身份+ZK 最小披露；链上假名 |
| 平台拖库/内部滥看 | 实名映射密文落库；令状+RA 双控；解锁上链 |
| 令牌重放/转卖/跨机 | 链级 nonce 烧毁+时间窗+SN 绑定 |
| 记录篡改/单方抵赖 | 遥测哈希链+检查点锚定+离线验真 |
| 轨迹曝光 | 轨迹零上链（只有链头）；TRAIL 证明结论不证明明细 |
| 飞手刷固件绕围栏 | **诚实声明为 TCB 边界**（与现业电子围栏同界）；实名+Remote ID 使黑飞残余风险不因本系统增加 |
| 时序侧信道（RA 关联子凭证与申请） | 声明+批量预签缓解 |

## 十一、检验体系（全批通用纪律）

1. **TDD 先红后绿**；负例是一等公民（每条拒绝路径有测试与演示位）。
2. **探针先于编码**：集成面形态（ArduPilot 参数支持/MAVLink 事件语义/电路宿主重建口径）先探针定谳再写实现。
3. **判决行纪律**：结论以直接可见判决行为准；数字标 [实测]/[推得]/[估算]；commit 先跑后写。
4. **门禁**：向量对拍门禁（国密库改动必触发）/链烟测/电路差分+变异/check.sh 聚合/doc_consistency 锚门禁/负例自证（撤防线必须变红）。
5. **宣称=实现**：说明书每断言挂可复现命令；性能数字标机器与线程；诚实边界主动成文。
